# 陪伴文案系统：触发、选择与管理（草案）

依据：[决定 054](../decisions/054-小生物陪伴提问与记忆回响.md)。首批内容：[companion-prompts-v2](companion-prompts-v2.md)。
状态：2026-09-16 草案，待审；审核通过后同步修订 054 的触发描述与 Core 0.24.0 合同。

## 1. 目标与原则

文案会从几十条长到几百条。系统要保证三件事：

1. **每句话都有此刻出现的理由**：只挂在真实事件上，不按时段或概率随机冒出来。
2. **越多越不吵**：条数增加只提高多样性，不提高出现频率。频率只由注意力预算决定。
3. **关系慢慢往里走**：先聊 Pibo 自己，再问你今天，最后问你是什么样的人；问过的事一定会被提起。

职责分工沿用现有规则：**Core 管规则**（预算、槽位优先级、层级解锁、冷却、确定性选择），**数据目录管内容**（台词、选项、回响和有限的条件标记），**平台管呈现**（气泡、手势命中、存储、卡片）。

## 2. 触发槽位

每个文案单元声明自己能出现在哪些槽位。槽位是平台能可靠观察到、Core 能枚举的真实事件：

| 槽位 | 发生时机 | 典型内容 | 备注 |
| --- | --- | --- | --- |
| `pat.after` | 一次拍一拍互动单元**说完最后一句**之后的下一次双击 | 机制、Pibo 自己、对当前健康事件的追问 | 首选槽位；用户正在互动，最不打扰 |
| `waking.first` | 进入 waking 后第一次拍一拍 | 早上的小事 | 每个清醒回合最多一次 |
| `return.short` | 离开 3–24 小时后回到首页 | 这段时间森林里发生了什么 | 进入后停留约 2 秒、无浮层才出现 |
| `return.long` | 离开 ≥24 小时后回到首页 | 配 boring，Pibo 自己在转圈 | 只自得其乐，不写委屈 |
| `event.meal` | 餐食识别成功、返回森林、观察结束之后 | 追问这顿饭 | 识别失败不触发 |
| `event.weather` | 天气由晴转雨／雪 | 雨落在头花上 | 与现有天气台词共用每日预算 |
| `event.boCollected` | `bo` 收取动画结束 | 头顶变轻了 | 不和收取反馈抢同一时刻 |
| `scene.grass` / `scene.river` / `scene.hammock` | 点草丛、河面、吊床 | 场景小对话、捉迷藏 | 单击即可，不需双击 |
| `hideseek.timeout` | 捉迷藏 90 秒无人找 | 自己出来 | 预算不允许时只出来，不说话 |

**不设槽位**：sleeping 全程、`dataUnknown` 中与授权修复相关的时刻、成就弹窗与发芽流程期间。

### 与现有拍一拍的关系

- 现有 467 条拍一拍 JSONL 不动，仍按 Core 27 个情境顺序轮换。
- 陪伴单元不插进拍一拍微章节中间。它只在一个拍一拍单元说完之后，占用**下一次**双击的文本机会。
- 同一次双击里，陪伴单元与拍一拍文本二选一，永远只出一句。

## 3. 一次选择的流程（Core 确定）

```
平台观察到槽位事件
  → ① 注意力预算：屏蔽状态？冷却？本次进入／今日已用？忽略退避？
  → ② 有到期回响吗？ 有 → 优先说回响（闭合旧对话），结束
  → ③ 取该槽位 + 当前状态的候选单元
  → ④ 过滤：条件标记、层级解锁、单元冷却、偏好已答不再问、话题冷却
  → ⑤ 排序：事件专属单元 > 场景单元 > 通用单元；同级内“最久没用的话题”优先
  → ⑥ 确定性加权选择（同一机会重进页面结果不变）
  → 平台呈现；记录 shown / answered / ignored
```

### 3.1 注意力预算

| 项 | 默认值 |
| --- | --- |
| 每次进入首页的主动句 | 1 |
| 每天提问（带选项的单元） | 1（关系第 1–3 天）→ 2（第 4 天起且最近回答率 ≥50%） |
| 每天主动句（提问 + 回响 + 场景台词 + 天气台词） | 3 |
| 与拍一拍共用文本冷却 | 3 秒 |
| 连续忽略退避 | 每 2 次跳过 1 天，最多 3 天；任一回答清零 |

场景点击（草丛、河、吊床）是用户主动发起的。它产生的**反应**不计入每日主动句，但其中带选项的提问仍计入每日提问数。

### 3.2 回响优先

回响比新问题更重要：问了不提，就只是问卷。

- 一条记忆可以有多个回响；每个回响声明槽位、最短间隔（默认 ≥10 分钟，偏好类默认 ≥1 天）、最多使用次数（默认 1）。
- 到期回响按“记忆越旧越先说”排序；当日记忆在日终前必须有一次机会被说出，否则静默过期。
- 回响可以带条件（例如“下雨时”）；条件不满足就等，不改写成别的句子。

### 3.3 层级解锁

| 层级 | 内容 | 解锁条件（默认） |
| --- | --- | --- |
| L1 | Pibo 自己、互动机制、眼前小事 | 首次接触完成后 |
| L2 | 你今天怎么样 | 累计回答 ≥3 次 |
| L3 | 你是什么样的人（偏好） | 累计回答 ≥7 次，且相处 ≥5 天 |

最近 7 天回答率低于 30% 时，暂时只从 L1 选。关系深度跟着用户的回应走，而不是跟着日历。

### 3.4 话题与去重

- 每个单元带 1 个话题标签（叶子、河、天气、吃、睡、身体、机制、`bo`、吊床……）。
- 同一话题 24 小时内最多出现 1 次；同一单元再次出现至少间隔 7 天；偏好类已回答且有效时不再问。
- 选择时同优先级内优先“最久没说过的话题”，避免连续三天都在聊吃的。

### 3.5 条件标记（有限枚举，不做表达式语言）

数据目录只能使用 Core 认识的标记，避免文案里长出第二套规则：

| 标记 | 含义 |
| --- | --- |
| `state` | 六状态之一或多个 |
| `patContext` | 现有 27 个拍一拍情境之一（如 `workout.run`、`thinking`） |
| `weather` | `rain` / `snow` / `clear` / `cloudy` |
| `phase` | Core 时段（早上／白天／傍晚／夜里） |
| `requiresAnswer` | 需要某条记忆存在（`unitId` 或 `unitId:optionId`） |
| `excludesAnswer` | 某条记忆存在时不出现 |
| `hideSeek` | `active` / `inactive` |

需要新标记时按 Core 发布流程加，不能在文案工具里自造。

## 4. 数据格式

一个陪伴单元一行 JSON（与拍一拍 JSONL 同一习惯，便于逐行审稿和合并）：

```json
{"id":"stable.leaf_on_sprout","status":"approved","kind":"question","slots":["pat.after"],
 "conditions":{"state":["stable"]},"tier":1,"topic":"sprout","retention":"today",
 "cooldownDays":7,"weight":10,
 "lines":["刚才有片叶子落在我头花上。","我没敢动。","你觉得我该甩掉它吗？"],
 "options":[
   {"id":"shake","label":"甩掉吧","reaction":["我甩了三下。它还挂着。"],
    "echoes":[{"id":"e1","slots":["pat.after","return.short"],"minDelayMinutes":600,"maxUses":1,
               "lines":["我今天偷偷练了甩头。","下次叶子掉下来，一下就能甩掉。"]}]},
   {"id":"keep","label":"顶着吧","reaction":["那我就顶着。脖子有点酸。"],"mood":"coolhide",
    "echoes":[{"id":"e1","slots":["pat.after","return.short"],"minDelayMinutes":600,"maxUses":1,
               "lines":["昨天那片叶子，我一直顶到晚上。","后来它自己掉了，我还找了一会儿。"]}]}],
 "custom":{"reaction":"pool","echo":"pool"}}
```

规则：

- **`id` 永久不变**。改错字、润色可以直接改文本；语义变了（问的事变了）必须新建 `id`，旧单元设为 `retired`。已保存的记忆继续指向旧 `id`，旧回响仍可说完。
- `status`：`draft` → `review` → `approved` → `retired`。只有 `approved` 会导出进 App。
- 选项 `label` ≤6 字；每个选项至少一个回响；`custom` 为 `pool` 时使用共享池，也可给专用写法。
- 占位符白名单：`{steps}`、`{sleepDuration}`（只在对应 patContext 条件下）、`{custom}`（必须在「」里）。

文件位置：鸿蒙 `entry/src/main/resources/rawfile/pibo-companion.zh-Hans.jsonl`；iOS 补差时字节一致复制。

## 5. 管理工具

扩展现有本机 **Pibo 文案工作台**（`Tools/pibo-copy-console`），增加“陪伴”页签，而不是另起一套：

1. **覆盖矩阵**：行是槽位，列是六状态，格子里是 `approved` 条数和缺口（例如 `event.meal × tired = 0`）。按矩阵补内容，而不是想到哪写到哪。
2. **单元编辑**：主句、两个选项、反应、回响、心情、条件、话题、层级、状态流转。
3. **自动检查**（保存和同步时都跑）：
   - 句长 8–40 字、选项 ≤6 字、选项恰好两个；
   - 每个选项有回响、`{custom}` 在「」里、占位符合法；
   - 禁用词：应该、必须、坚持、继续保持、还没完成、主人、Emoji、连续感叹号、波浪号；
   - 同话题单元数、重复主句、`id` 唯一、`retired` 单元不被新回响引用；
   - 条件标记只允许 §3.5 列出的枚举。
4. **选择模拟器**：选状态、槽位、天气、相处天数、已有回答，调用与 App 同一份 Core 规则，看这次会选出哪条、为什么没选出其他条。用于审稿，不修改真实记忆。
5. **同步**：只导出 `approved`，原子替换鸿蒙资源，备份旧版；与现有拍一拍同步流程一致。
6. **真机验收**：沿用“拍一拍场景验收”的隔离调试会话，增加强制槽位、强制单元、模拟离开时长、时间偏移和清空记忆。

## 6. 数据回看与淘汰

埋点只记 ID，不记用户写的文字：

| 指标 | 用途 |
| --- | --- |
| 单元出现 / 回答 / 忽略 / 自定义比例 | 找出“没人接”的问题 |
| 回响出现后 24 小时内是否回访 | 判断记忆是否真的有用 |
| 每个选项的选择比例 | 两个选项严重失衡说明其中一个不自然 |
| 层级停留 | 用户是否卡在 L1 |

每两周复盘一次：忽略率 >70% 的单元改写或退役；选项比例 >90/10 的改选项；回响后回访明显更高的话题优先扩写。

## 7. 扩写节奏

- 每批只补覆盖矩阵里的一个缺口，先写 3–5 条校准声音，审过再扩到 10 条。
- 批量生成可以复用现有 LLM 批量文案 Prompt，但需补一版“陪伴单元”说明（槽位、选项、回响、禁止事项）；导入后一律为 `draft`，人工审核才能 `approved`。
- 目标规模：第一期 ~40 条；两周试用后按数据扩到 ~120 条，每个“槽位 × 状态”至少 3 条。

## 8. 对计划的影响

- 决定 054 与 Core 0.24.0 合同中的“时段首次进入”触发，改为本文 §2 的槽位枚举。
- Core 新增：槽位枚举、层级解锁、话题冷却、回响优先与到期排序、条件标记匹配。
- 平台新增：`event.meal`、`event.weather`、`event.boCollected`、`scene.river`、`scene.hammock` 的事件接线；草丛之外的河面、吊床点击复用吊床的命中写法。
