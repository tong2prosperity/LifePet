# 协作方法：先确定命题，再审视具体瞬间

采用批次协作。每轮先围绕同一层级一次性提出完整问题组，由用户集中回答，再统一归纳。
在基础命题尚未确定时，不提前用情节感染力替代价值判断；进入情节阶段后，
再由 Codex 切换不同角色审视同一个瞬间。

每个批次回答后，只有答案之间存在影响方案的关键冲突时才补问，单批最多补问 3 个问题。

## 六个工作角色

1. **生活观察者**：寻找现实中具体的动作、停顿、遮掩和自相矛盾。
2. **编剧**：把观察压缩成最小戏剧单位，判断人物想要什么、在怕什么、为什么不直说。
3. **演员**：检查台词之外的行为，寻找类似吞咽、回避视线、欲言又止的可见细节。
4. **产品叙事设计者**：判断这个瞬间能否自然发生在打开、等待、运动、睡眠、回访等真实使用场景中。
5. **陌生用户**：不读取设定集，只凭首次体验判断是否看得懂、是否相信、是否在意。
6. **冷酷编辑**：删除解释、套路和自我感动，检查用户能否用自己的经验补全留白。

用户是最终导演：决定什么是真实的、什么值得留下，以及何时算“拍板”。

## 基础设定阶段

依次讨论产品存在理由、对人的判断、期待的改变、人与 Pibo 的关系、媒介与伦理边界。
这一阶段以提出假设、寻找反例和澄清分歧为主，不急着写台词或剧情。

## 情节阶段推演模板

### 1. 生活母题

先说一个人们真实经历过的处境，不谈 Pibo。例如：想被关心又不愿承认、离开太久后不敢直接道歉、
明知疲惫却不肯停下来。

### 2. 内部矛盾

写清人物同时存在的两股力量。没有矛盾，就只有功能反馈，没有戏。

### 3. 最小可见动作

寻找一个无需旁白也能被感知的动作、停顿或选择。优先身体和行为，最后才是台词。

### 4. Pibo 化

再判断这个瞬间由 Pibo 做出来时会有什么独特质感。此时才使用它的外形、语言和可能的世界观材料。

### 5. 产品落点

明确触发条件、出现位置、持续时间、用户能否打断，以及重复出现后是否仍然成立。

### 6. 陌生人测试

不提供背景说明，验证用户能否回答：

- 它刚才想做什么？
- 它为什么没有直接做？
- 我感到了什么？
- 我是否想再来看它一次？

### 7. 拍板

分别标记为：`保留观察`、`候选方案`、`已拍板` 或 `放弃`。只有“已拍板”内容进入 `decisions/`。

## 拍板标准

一个方案至少要满足：

- 来自可辨认的生活经验，而不是只在设定内部成立。
- 不读世界观说明也能感到人物当下的欲望或矛盾。
- 行为比解释多，留白能够被用户经验填充。
- 与健康产品的真实使用时刻相连，而不是外挂剧情播放器。
- 重复体验不会迅速退化成机械提示。
- 不通过指责、卖惨或道德压力换取留存。
