# 2026-07-23 · 基础逻辑批次归纳

> 状态：第一轮 batch 完成。已生成《Pibo 基础逻辑宪章 v0.1》，只剩 3 个关键冲突需要集中回答。

## 已经较清晰的部分

- 服务忙碌中反复忘记照顾身体、可能会看数据但难以持续行动的人。
- 健康是核心价值，App 是功能载体，叙事表达对健康的理解。
- Pibo 让缓慢、不可见的身体变化获得可见的情感表达。
- Pibo 拥有独立世界观与故事线。
- 故事采用固定骨架、少量分支、按章节持续更新，不依赖 LLM 动态生成。
- MVP 以累计活动与少量特殊事件解锁故事，用户初期主要是见证者。
- 系统负责准确健康事实，Pibo 感知象征状态，不作为医学权威。
- 功能和故事先各自成立、偶尔连接，再逐步深化。
- 初见依靠形象吸引，长期依靠故事建立关系。

## 压力测试发现的冲突

### 1. 共同经历者与能量依赖

若 Pibo 必须获得用户健康能量才能完成使命，用户事实上承担了推进或解救 Pibo 的责任，
这可能与“绝不是被照顾者”冲突。需要明确缺少能量对 Pibo 本身造成什么后果。

### 2. 有生命周期的 App 与长期健康价值

若 Pibo 完成使命后离开、App 对个人关闭，故事会形成有力终点；但健康是终身需求，
照片、HRV、睡眠等工具也可能仍有价值。需要明确离开的是角色故事、这一段关系，还是整个产品。

### 3. 低活动暂停故事与目标用户

最忙、最疲惫、最少运动的人恰恰是目标用户。如果他们得到最少故事，故事门槛可能成为惩罚，
并使 Pibo 的关系重新变成绩效交换。无授权、没有数据、活动很少和长期不打开也不应被视为同一种情况。

## 模拟用户压力测试

- **会看睡眠但不运动的人**：如果故事长期停住，可能只剩数据工具，无法建立关系。
- **压力大、睡眠差的人**：若植物持续低迷或 Pibo 无法推进使命，容易产生羞耻和负担。
- **高活动用户**：若纯按能量解锁，可能快速消费故事，健康行为退化成刷进度。
- **隐私敏感用户**：不授权不代表不关心健康，完全停摆会把权限变成叙事门票。
- **完成故事的长期用户**：若整个 App 关闭，已经建立的健康工具习惯和照片资产将失去承载位置。

## 本轮仅需补问的 3 个问题

1. 当用户没有提供足够健康能量时，Pibo 本身究竟会发生什么？
2. Pibo 完成使命离开后，App 的健康功能、用户数据和双方留下的内容是否继续存在？
3. 请分别定义“未授权”“活动很少”“长期未打开”三种情况下，故事应该如何变化，以及哪些后果绝不能发生。
