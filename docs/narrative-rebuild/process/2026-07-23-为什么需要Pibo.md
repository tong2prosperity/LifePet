# 2026-07-23 · 为什么需要 Pibo：人与自己的中间态

> 状态：过程推导。其中“共同经历者为主体、保留镜子、排除被照顾者”已于
> [`decisions/001-Pibo角色关系模型.md`](../decisions/001-Pibo%E8%A7%92%E8%89%B2%E5%85%B3%E7%B3%BB%E6%A8%A1%E5%9E%8B.md) 拍板；其余内容仍为候选。

## 初始理解

人与人发生冲突时，第三方有时能提供缓冲：同一句话由对方直接说出，容易被体验成攻击；
经过一个被双方信任的中间位置重新表达，人才可能听见话语背后的需要。

人与自己的关系也存在类似冲突：

- 当前的我想继续工作，身体却要求停下；
- 理性的我知道健康重要，焦虑的我认为休息可耻；
- 我希望照顾未来的自己，却只感受到眼前任务的压力；
- 身体已经发出信号，负责维持运转的那部分自己却不愿承认。

健康提醒直接对用户说“你应该休息、运动、早睡”时，容易加入冲突的一方，成为又一个要求和评分者。
Pibo 的可能价值是提供第三个位置，让人暂时不必直接审判自己，也能够接近自己的真实状态。

## 候选定义

> Pibo 是人与自己的身体、情绪和生活重新建立关系时的中间态。

它不是代替用户理解身体，也不是把健康命令换成可爱台词，而是把原本难以直接面对的自我关系，
转化为一段可以观察、回应和慢慢理解的关系。

## 这种中介如何发生

### 1. 外化

“我已经很累”可能伴随软弱感和负罪感；当 Pibo 先表现出对某种状态的感受，
用户可以从第三人称距离观察它，而不必立刻为自己辩护。

### 2. 缓冲

Pibo 不站在“自律的我”一边批评“没有做到的我”，也不替任何一方裁决。
它接住身体信号，让冲突从命令与反抗，变成一次关系事件。

### 3. 投射

人可能暂时更容易承认“它需要休息”“它今天没有精神”，然后逐渐辨认：
自己关心的其实也是自身状态。

### 4. 返还

中介的终点不是让用户永远依赖 Pibo 才能照顾自己。Pibo 借走用户暂时无法给自己的关心，
最终应当把这份关心还给用户本人。

由此得到一句候选表达：

> 人有时无法直接善待自己，却愿意先善待一个与自己相连的生命；Pibo 借走这份关心，再把它还给人自己。

## 为什么图表、提醒和普通教练难以替代

- **图表**能够描述状态，却不能承接投射和关系。
- **提醒**能够打断行为，却很容易成为又一个外部要求。
- **教练**通常代表目标、标准和纠正，仍可能加剧“应该做到”的冲突。
- **生命角色**可以被在意、被误解、保持沉默并作出回应，允许关系在没有结论时继续存在。

因此 Pibo 的必要性不在于更可爱，而在于它能建立一个非命令式的第三位置。

## 必须警惕的失败方式

### 1. 用 Pibo 制造亏欠

若用户没有运动，Pibo 就受伤、哭泣或消失，这不是缓冲，而是把健康焦虑改造成情感勒索。

### 2. 让投射停在 Pibo 身上

如果用户只学习“养好 Pibo”，却没有更理解自己的身体，中介就变成了替代物。

### 3. 把命令藏进可爱外壳

“Pibo 想让你站起来”如果本质仍是通知和打卡，并没有形成新的关系结构。

### 4. 假装拥有医疗权威

Pibo 可以感知、陪伴和表达，但不能把有限健康数据包装成诊断，也不能替用户解释所有身体经验。

### 5. 永久占据用户与自己之间的位置

真正的桥梁允许人走过去。若产品必须不断增强依赖才能留存，就违背了中间态的意义。

## 对后续人物设计的要求

如果这个方向成立，Pibo 至少需要：

- 不以用户达标为唯一目标；
- 不总站在正确的一方；
- 有沉默、误解和不确定，而不是实时讲解健康数据；
- 能承接用户的关心，但逐渐把注意力引回用户自身；
- 允许用户离开、反复和重新回来，不把关系变成债务；
- 拥有一定自主性，否则只是拟人化通知。

## 下一步验证

接下来不急着写背景故事，而应比较三种“中间态”模型：

1. **镜子**：Pibo 映照用户状态，让用户看见自己。
2. **被照顾者**：用户先照顾 Pibo，再学会把关心返还给自己。
3. **共同经历者**：Pibo 与用户都受同一段生活影响，双方一起学习，而非单向照顾。

三种模型会产生完全不同的权力关系、情感风险和故事结构，需要先判断哪一种最符合根命题。
