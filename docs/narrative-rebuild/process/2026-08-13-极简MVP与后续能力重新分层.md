# 极简 MVP 与后续能力重新分层

> 日期：2026-08-13
> 性质：用户确认的产品重置检查点；包含已确认方向与待论证问题，不把待定项冒充最终规格。

## 为什么重置

此前方案同时承载健康解释、`bo` 经济、共同物件、功能门控、长期主线和多项工具能力。
作为 App，它很难像线性媒介一样保证用户完整观看事件，也很难让用户在短时访问中统一
感知关系推进。当前优先从“用健康数据养成 Pibo”的最初理念重新建立直接因果。

## 已确认的核心

近期 MVP 冻结为：

> 真实睡眠与活动使 Pibo 本身发生可见变化，头顶生长并成熟一枚可拔取的 `bo`；
> 累计生活继续给 Pibo 或共同森林留下永久成长。

正向变化必须直接落在 Pibo 身上。用户授权后应尽快看懂数据与 Pibo 变化的因果，
近期不再以事件 04–21 的完整剧情制作作为核心循环成立的前提。

## 已确认的路线图能力

- 餐食相机：保留，具有可能的收费与高频记录价值；
- Walk Doodle：保留，具有把真实行走转成创作痕迹的留存价值；
- Shadow Pibo：保留，目标是让用户看到好友 Pibo 的状态映射，不直接暴露好友原始
  健康数据；正向变化落在 Pibo 身上是该能力成立的基础。

三项能力可能不属于当前极简 MVP。具体版本、入口、收费、隐私、状态新鲜度和物件关联
仍需逐项确认。

## 重新打开的伦理边界

用户明确允许 Pibo 受苦，因此决定 027 的绝对禁止不再控制后续设计。但当前只确认
“可以”，尚未确认：

- 哪些数据或事件能够触发；
- 表现为疲惫、饥饿、疼痛、疾病、受困还是其他状态；
- 是否影响能力、关系、成长或库存；
- 用户如何帮助恢复，以及能否自然恢复；
- 缺失数据、权限拒绝和用户长期离开如何处理；
- 哪些设计会越过情感连接，变成负罪、强迫或健康误判。

以上问题冻结前，不直接实现新的惩罚规则。

## 共同物件尚未被否定

用户直觉认为“解锁物件获得新能力”有意义。现行决定 032 和工程映射暂不撤销，下一轮
需要验证：

1. 物件与能力是否具有无需长篇世界观也能理解的因果；
2. 功能是否因为门控而过晚被发现；
3. `bo` 解锁、订阅付费和持续服务成本分别负责什么；
4. 解锁后是否在 Pibo 或森林中产生永久、可见的变化；
5. Shadow Pibo 的网络效应是否会被双方都需解锁的门槛阻断。

## 工程事实

当前 iOS Home 已经是固定单屏 SpriteKit 森林，代码中没有 Studio/Gym 页面或横向漫游。
`Pibo/Features/Games/` 是被发布开关收起的工程库存，不是仍在线的 Gym 页面，因此本轮
没有代码需要删除。餐食相机与 Walk Doodle 的 Release 开关目前仍为开启；在版本归属
拍板前不提前关闭。

## 下一轮讨论顺序

1. 定义 Pibo 的正向成长究竟改变身体、动作、能力还是共同空间；
2. 定义 Pibo 可以受苦的安全而有效的产品边界；
3. 逐项验证共同物件与能力的映射；
4. 比较餐食相机、Walk Doodle、Shadow Pibo 对获取、留存、付费和关系的不同作用；
5. 据此冻结 MVP、V1.1、V1.2 的版本表，再修改 Release 开关和工程范围。

使用 Image Gen 生成第一张七状态探索板。结果与提示词见

独立 SVG、统一锚点和转场。
