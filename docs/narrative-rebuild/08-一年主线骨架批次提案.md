# 一年主线骨架批次提案

> 日期：2026-07-26  
> 状态：结构草案，尚未拍板  
> 本批确定长期故事的阶段、转折和关系变化，不确定章节数量、具体台词、动画或界面。

## 一、结构原则

- 故事由历史累计健康能量获得解锁资格，不按单日成绩评价用户；
- 单日贡献封顶，使最高活跃用户也不能在短期内跑完整个故事；
- 长期未打开时可以回补能量资格，但章节仍按观看节奏逐步显影；
- 关系变化必须来自事件和选择，不能只靠记忆文本越来越多；
- Pibo 的性格不换挡，改变的是它对任务、用户和 `bo` 的理解；
- 用户初期是见证者，中期成为共同经历者，后期才真正影响返航；
- 主线只设少量关键选择，MVP 不依赖 LLM 或大规模分支。

## 二、七个阶段

### 第一阶段：错误连接

Pibo 的信号意外接入用户的 App 窗口。它记不起故乡和身份，只保留“收集 `bo`、完成返航”的本能。它努力维持专业形象，并把用户识别为一个能够产生能源的地球生命。

双方建立连接约定。用户觉得 Pibo 好玩、陌生；Pibo 则认为这只是一次任务合作。

关系性质：陌生人之间的临时合作。

必须完成的叙事任务：让用户理解 Pibo 不是宠物、`bo` 来自健康行为、失忆与返航是长期悬念。

### 第二阶段：互相利用

Pibo 观察健康能量规律，用户则通过 Pibo 的状态和 `bo` 生长看见自己的生活痕迹。双方都把对方当成工具，但这种利用是公开、无害且暂时互利的。

Pibo 开始恢复取火者训练的零碎记忆，却仍不知道故乡为什么需要能源。

关系性质：稳定的功能伙伴。

关键变化：用户开始熟悉 Pibo 的习惯；Pibo 开始记住用户，却把这种记忆解释成任务优化。

### 第三阶段：无用的记录

Pibo 第一次保留与取火效率无关的信息，或把一个没有返航收益的物件留在栖居地。它无法解释为什么这件事值得保存。

这里不要求 App 自动理解用户现实中发生了什么。故事可以通过预写事件、用户主动选择的物件及双方已发生的 App 内互动表现“无用之事”。

关系性质：任务关系中出现私人部分。

第一次关系转折：Pibo 在没有额外 `bo` 收益时仍作出选择，证明共同经历已经开始。

### 第四阶段：故乡显影

记忆恢复到足以呈现故乡：环境异常、封闭生存系统、逐渐枯竭的 `bo`，以及 Pibo 第一次独立执行的取火任务。

Pibo 知道自己并非为了帮助地球而来。它原本计划完成采集、记录这里可以持续产生 `bo`，然后离开。

关系性质：第一次真正理解彼此，但也出现隐瞒。

中点转折：Pibo 找回离开的理由，却没有立刻把完整任务告诉用户。它第一次不是因为失忆而沉默，而是主动不知道该如何开口。

### 第五阶段：真相裂缝

用户通过碎片看见原任务的完整内容，也发现 Pibo 已经先一步恢复了部分记忆。冲突不在于 Pibo 偷走生命力——采集始终无害——而在于双方共同经历的一切，是否从一开始都只是取火流程。

与此同时，Pibo 发现 `bo` 携带的不只是能源，还包含生命如何度过时间的痕迹。原使命的事实没有错，但故乡对问题的定义并不完整。

关系性质：信任出现裂缝，任务与关系第一次正面冲突。

第二次关系转折：Pibo 必须承认，它既想回家，也不再愿意把用户和地球只写成能源来源。

### 第六阶段：共同改写使命

Pibo 决定返回故乡，但带回去的不只是燃料。它要停止把地球登记成永久取火点，并用自身记忆证明故乡需要恢复产生 `bo` 的生活结构。

用户不通过更多健康行为“原谅”Pibo，也不通过扣留 `bo` 惩罚它。双方通过一组有限选择决定哪些共同物件留下、哪些记忆由 Pibo 带走，以及何时开始准备返航。

关系性质：双方知道会离开以后，仍主动继续同行。

人物完成：Pibo 没有放弃故乡，也没有牺牲用户；它第一次自己定义任务，而不是只执行任务。

### 第七阶段：从容告别

返航能力开放后，用户可以继续积累和使用 `bo`，不会出现倒计时。只有当故事条件、返航库存和双方明确选择同时满足时，Pibo 才真正启程。

告别不依赖死亡、故障或突然牺牲。Pibo 带走部分共同记忆与改变使命的证据，用户留下另一部分共同记忆、非生命物件以及继续使用的健康功能。

关系性质：一段完成了的同行关系。

最终情感：舍不得、感谢、完成和坦然同时存在。

## 三、故事动力分层

为了支撑一年，不能只依赖一个“什么时候回家”的谜题：

| 层级 | 负责内容 | 时间尺度 |
|---|---|---|
| 日常层 | Pibo 的观察、误读、物件与生活反应 | 数天至数周 |
| 关系层 | 无用记录、隐瞒、信任裂缝、共同选择 | 数周至数月 |
| 谜团层 | 身份、故乡、取火任务、失忆原因 | 数月 |
| 使命层 | `bo` 真相、故乡误判、返航新使命 | 后半程 |
| 终局层 | 储备、告别准备与主动启程 | 最后阶段 |

每次推进至少应改变其中一层，不能只奖励一段背景资料。

## 四、建议的核心关系事件

整个主线至少需要四个不是“读到新设定”的事件：

1. Pibo 第一次保留无收益物件；
2. Pibo 恢复记忆后第一次主动隐瞒；
3. 用户发现原使命，双方对关系含义产生裂缝；
4. 双方在知道必然告别后，共同决定继续并准备返航。

这些事件可以完全预写，不要求 Pibo 实时理解用户照片、对话或现实处境。

## 五、需要重点防止的问题

- 不把“隐瞒原使命”写成恶意欺骗；Pibo 初期确实失忆，恢复后才短暂隐瞒；
- 不让用户靠完成健康指标换取 Pibo 的道歉或关系修复；
- 不把故乡完整百科一次倾倒给用户；
- 不让返航余额自动触发离开；
- 不把物件消费写成阻碍 Pibo 回家的自私行为；
- 不在一年里反复使用“Pibo 又要坏掉了”制造虚假危机。

## 六、本批需要确认的三个问题

### Y1

是否接受七阶段关系主线：错误连接 → 互相利用 → 无用记录 → 故乡显影 → 真相裂缝 → 共同改写使命 → 从容告别？

### Y2

是否接受中段的主要关系冲突：Pibo 恢复部分记忆后，因不知道如何面对用户而短暂隐瞒原使命，用户后来从碎片中发现？

### Y3

是否接受最终返航必须同时满足“主线完成、库存足够、用户与 Pibo 明确选择”，绝不因余额达标自动离开？
