## 一句话方向

Pibo 不是需要用户照顾的电子宠物，而是一名与用户临时合作的外星取火者。用户的睡眠、步行、站立和运动使 `bo` 生长；双方从互相利用走向共同理解健康、生活和效率的意义，最后由用户与 Pibo 共同决定是否返航。

## 当前进行到哪里

### 已拍板

- 产品为什么需要 Pibo，以及 Pibo 是“共同经历者＋镜子”，不是被照顾者；
- Pibo 的人物基础、故乡历史、原使命和返航终局；
- 七阶段、二十一个核心事件的完整主线；
- `bo` 的产出、库存、消费和返航基本关系；
- 健康数据、权限、读心和用户留白边界；
- 故事与核心功能分离，用户可以长期忽略故事；
- 森林季是 Pibo 观察地球后主动制造的当前空间，环境与交互表现以后可以改变；
- 主页发现、混合载体展开、共同记录回看的 App 叙事结构；
- 事件不自动播放、允许中途退出、完成后留下持续变化；
- 主线完全预写，不依赖 LLM 或 VLM 动态生成；
- 事件 01“错误抵达”的第一轮具体深化。

### 正在讨论

事件 02“临时约定”的具体呈现。当前提案尚待最终确认：

1. 约定采用清楚、可撤回的临时合作，不包装成命定契约；
2. Pibo 表达自己的请求，系统授权页准确说明权限，两者分开；
3. 至少授权一种可形成健康能量的数据来源后，事件才完成；拒绝时故事暂停且不施压。

### 尚未进入

- 事件 02–21 的完整分镜、动画、漫画、视频和交互设计；
- 每个阶段的具体环境变化、交互入口变化和循环台词池；
- 故事门槛、单日封顶、追赶间隔和返航库存等数值；
- 共同记录页面的信息架构与视觉设计；
- 新叙事对当前 App 功能和代码的迁移计划。

因此，当前可以进行概念设计和技术预研，但不能把未深化的事件直接当作最终开发需求。

## Pibo 是谁

- 第一次独立远行、努力显得可靠的年轻取火者；
- 认真、好奇、直接、讲程序、自尊心强；
- 不喜欢被当成宠物或幼儿，也不是用户的健康教练；
- 记忆与翻译受损，因此初期会乱码、断句和缺词；
- 它的性格不会从“冷漠”切换成“温柔”，变化的是判断和行动；
- 它不擅长说安慰话，关心主要通过记住、等待和作出选择表现。

## 世界与故事

Pibo 来自同一宇宙中的外星文明。故乡曾因长期环境异常进入封闭生命系统。这个系统拯救了数代生命，却也逐渐让活动、睡眠、光照和身体节律高度受控，生命自身产生的 `bo` 越来越少。

故乡把问题理解为“外部能源不足”，于是派出取火者寻找新的 `bo` 来源。Pibo 来到地球后失去部分记忆，偶然与用户建立连接。它最初把用户理解成能源节点，后来才明白：`bo` 不是矿物，而是生命实际睡眠、活动、休息和度过时间后形成的结果。

新使命不是摧毁故乡系统或复制地球森林，而是在不关闭生命支持的前提下，验证故乡生命能否重新产生自己的 `bo`。

## 七阶段主线

| 阶段 | 关系与故事变化 |
|---|---|
| 1. 错误连接 | Pibo 与用户偶然相遇，只建立临时合作 |
| 2. 互相利用 | 用户获得健康反馈，Pibo 获得 `bo` |
| 3. 无用记录 | 双方第一次保留没有任务收益的互动和物件 |
| 4. 故乡显影 | Pibo 恢复故乡、自然生态与避难历史的记忆 |
| 5. 真相裂缝 | 用户发现自己也是取火计划的验证对象 |
| 6. 共同改写使命 | 双方寻找原生 `bo` 的有限证据，提出安全试验 |
| 7. 从容告别 | 返航成为双方选择，不靠死亡、催促或牺牲推动 |

完整事件摘要见[二十一个主线事件 v0.3](../16-%E4%BA%8C%E5%8D%81%E4%B8%80%E4%B8%AA%E4%B8%BB%E7%BA%BF%E4%BA%8B%E4%BB%B6-v0.3.md)。

## 产品循环与 `bo`

基本链路：

> 授权健康数据 → 睡眠、步行、站立和运动形成生长进度 → Pibo 头顶长出实体 `bo` → 用户拔下 → 进入库存

- 同一种 `bo` 可以用于解锁共同物件，也可以为返航做准备；
- 消费后的 `bo` 不能再次用于返航，但用户以后仍可继续积累；
- 历史产出量负责故事资格，当前库存负责消费和返航；
- 库存达到要求只代表“可以返航”，绝不自动离开；
- 返航必须同时满足主线完成、库存足够和双方明确选择。

## 所有设计必须遵守的规则

1. Pibo 是共同经历者，不是宠物、婴儿或被照顾者；
2. 低活动、低库存、长期不打开不会使 Pibo 受苦、死亡、责怪用户或关系倒退，但会让高耗能行动、使命准备和部分故事节点更晚发生；
3. 睡眠同样是重要健康来源，不以高强度运动作为唯一正确答案；
4. 核心健康功能从开始使用后即可使用，不由故事进度解锁；
5. 故事不会自动播放或弹窗打断功能，用户必须主动进入；
6. 每个阶段都允许无限期停留，剧情时间不直接等于现实时间；
7. Pibo 只能看见授权数据怎样形成能量，不能知道用户为何行动、是否开心或在想什么；
8. 用户没有固定身世，故事不能擅自补写用户的家庭、工作或情绪；
9. 当前发生的关系变化要通过 Pibo 的行动、选择和空间变化呈现，不能只写在档案里；
10. 用户是否感动不作为通关条件，产品只负责把关系变化清楚呈现；
11. 主线为固定预写内容，健康数据只决定资格和填入少量事实；
12. AI、自动化和故乡技术不是反派，问题是应急生存方式长期替代了生活；
13. 告别没有倒计时，不用疾病、故障或牺牲制造压力；
14. 返航后关闭的是 Pibo 的故事窗口，健康功能、历史数据和共同记录继续保留。

## App 如何讲故事

采用三层结构：

1. **主页发现**：用户先在 Pibo 当前空间看到环境、动作、信号或物件变化；
2. **事件展开**：按照内容选择主页实时动画、视频、漫画、静态分镜、对话或交互；
3. **共同记录**：已完成事件进入时间线，供用户回看和整理。

标准事件流程：

> 条件满足 → 主页出现不打断功能的提示 → 用户主动触发 → 事件展开 → 完成最后互动 → 回到已变化的主页 → 写入共同记录

## 当前森林季

- Pibo 抵达地球后观察过不同环境，因为觉得森林舒服而制造了森林季；
- 森林季不是故乡原貌，也不是永远不变的固定主题；
- 故乡过去存在类似森林的自然生态，但 Pibo 这一代几乎没有真正生活在其中；
- 后续可以通过环境甚至交互方式的变化讲故事，但核心功能持续可达。

## 旧内容隔离

旧功能、旧世界观和当前已发布机制不会自动沿用到新叙事。尤其不能直接带入：

- 低步数或睡眠不足让 Pibo 烦躁、受苦；
- 未按时拔取就清空积累；
- 拍照默认产生健康能量；
- 魔丸人格阶段；
- 旧上滑二楼和旧多主题世界观。

需要复用任何旧功能时，必须重新经过新叙事规则审查。本简报也不授权直接修改当前线上产品。
