# 057：像素化重构与可见成长

日期：2026-10-19。状态：用户已批准方向，HarmonyOS 先行（分支 `feature/pixel`），iOS 冻结至像素版验证通过后一次性补齐。批准原话：「之前批准的都可以修改。根据你的思考，重新定义。」「没问题，以这个分支为基础，然后切到 feature/pixel 分支开始执行。」

## 背景

- 用户反馈：表现力弱、变化少，不知道这里能做什么、该做什么。
- 生产成本：角色是手绘母版经 `tools/prematch` 转成的多边形变形数据（约 6.4MB、21 个片段），每个新动作或场景都要数天，「森林里看得见的痕迹」（056）因此被推迟。
- 结构问题（按 Core 0.27.0 常量粗算）：`bo` 约 1.5–2 天成熟一个；物件成本 1／3／6／10，MVP 只开放前两件，累计 4 个 `bo`（约第 6–8 天）后再没有可投入的去处。Pibo 的外形和能力两周内不变。两周试用的后半段主循环是空的。
- 当初并没有一份「删除好感度／成长值」的决定；PRODUCT 一直写着「成长有两条线」，只是从未让它可见。Core 的陪伴分层（3 次回答、7 次回答、相处 5 天）已存在但 UI 不显示。
- 决定 051 要求的 5 人测试尚未执行，「不知道该做什么」目前是开发者观察，切片阶段需要补齐对照证据。

## 决定

### 一句话

一只由你的真实生活喂养、看得见地长大、会把森林慢慢布置起来的像素小生命。

产品排序改为：**因果可见、成长可见、每天有事可做**，其次才是克制与留白。

### 画面：程序式像素

- 首页舞台、角色、森林、物件、气泡和主要 UI 外壳改为程序式像素画：固定低逻辑分辨率、整数倍放大、最近邻采样、限定调色板。
- 昼夜、天气、状态氛围优先用调色板变化表达；角色由参数化形状、部件和小图章生成，动作用参数曲线按步进帧播放。
- 允许少量手工小图章（表情、图标），目标是新增一个动作从「数天」降到「半天以内」。
- 中文正文、设置、健康详情继续用系统字体；像素中文字体只用于标题与气泡，许可须为 OFL 或同等可商用。

### 恢复可见成长（不惩罚、不出售）

1. **成长等级**：Pibo 经验来自真实健康形成的 `bo` 能量、每日心愿与互动（互动每日封顶）。经验条和等级可见；升级有表演，并带来体型、头草、配饰、新动作等外观变化。早期升级快、后期放缓。
2. **熟悉度**：由相处天数、互动、陪伴回答累积，只增不减，以心形格显示，每级解锁新的反应动作或台词类别。并入现有陪伴分层，不另起计数；相处天数仍只有 056 的一个定义。
3. **今日小心愿**：Pibo 每天提出 2–3 个小愿望（拍拍我、给我看看你吃了什么、按你自己的基线走一段路等）。完成有奖励；未完成无惩罚、不计连续天数、不发催促通知。
4. **装饰目录**：`bo` 的去处改为按等级逐步开放的程序生成像素装饰目录，不再在第四件物件处终止。吊床、状态观测仪保留为最初两件及其功能。
5. **森林痕迹**：时间线里的共同的第一次与 Pibo 的小事，在森林里留下持续可见的像素痕迹；文字时间线保留为回看页。

### 保留（行为合同不变，表现换成像素）

- 六个 Core 主状态与真实健康：不伪造数据，缺失不等于低健康。
- 拍一拍（双击为有效拍一拍，单击仍有轻回应）、陪伴提问与记忆回响、运动回应留在森林（055）。
- `bo` 头顶容器、成熟与收取（048）。
- 餐食相机只在后端确认 `is_food` 后成功；成功的餐食额外生成像素食物贴纸，可放进森林。
- 足迹与睡眠详情的数据视图可暂时沿用现有图表，外壳换成像素风。

### 移出路线图

Shadow、小游戏、会员购买入口、散步涂鸦、风铃与铃兰灯物件链不再「隐藏保留」，像素版切换完成后与旧美术一起删除；账号、余额、已拥有物件的权属数据不删除。小说与世界观（035–042）降为背景素材，只保留「异世界来客」一句话设定。

### 工程方式

- 同一个 app（`com.piboworld.app.pibo`）、同一个仓库，在 `entry` 模块内新建像素表现层；服务、存储、Core 桥沿用。当前版本照常上架作为 v1 与埋点基线，像素版作为 v2 更新。
- 先做一周可推翻的切片；通过后逐页替换，切换完成的同一轮整批删除旧表现层与移出路线图的功能。
- 成长、熟悉度、心愿、装饰目录成本与开放、痕迹选择、「种子 → 部件／调色板」的确定性选择属于跨平台规则，必须先进 `pibo-core` 正式标签；切片阶段只允许 Debug 手动参数演示，不在 ArkTS 写规则。
- 像素栅格化属于平台表现，不进 `pibo-core`。iOS 是否共享独立栅格化库，在 iOS 补齐前另行决定。

## 切片判定

通过须同时满足：

1. 新增一个状态动作从提出到真机 ≤ 半天；新增一个调色板变体 ≤ 1 小时；比历史基线至少快 3 倍。
2. 与当前包交叉顺序的 5 人测试中，「30 秒内说出可以做什么」像素版 ≥ 4/5 且高于旧版。
3. 「像同一只 Pibo、可爱」评分不低于旧版。
4. 真机舞台不掉帧，耗电与首帧不劣于旧版。

角色评分明显变差或成本没有快 3 倍即停止像素化；若新旧两版第 2 条都差，先发布成长与心愿的 Core 规则，再推进画面。

## 修订与废止

- **022 现有产品与资产优先**：废止。
- **051 单人陪伴 MVP 边界**：废止其「不加场景或整批动作」「不加任务、签到」「两轮 polish 后进入试用」与隐藏保留条款；五条验收旅程与「真实健康不可 Mock」保留，用于像素版验收。
- **053 恢复原动画**：被像素表现整体替代；Core 动画语义 ID 继续使用。
- **056 文字版时间线**：「森林痕迹以后再做」改为本决定范围内实现。
- **043、050 及物件链中的风铃／铃兰灯**：移出路线图。
- **028**：继续生效。成长、熟悉度、`bo` 不可购买或加速。
- **PRODUCT**：一句话定义与核心体验以本决定为准，待像素版切片通过后改写 PRODUCT 正文。

## 附录：成长规格（2026-10-19，用户批准「完整实现初版」）

用户要求在切片之上直接做完整初版：「pibo 当前的像素形象还不够贴近非像素版本，制定一个有野心的规划，能够真的让用户感受到 pibo 的成长与用户的健康数值的绑定，合理设计及时反馈，把有趣内容，一些吐槽的文案也加进来。」「surprise me。」所有数值都由 `pibo-core 0.28.0` 提供，平台只负责表现。

### 形象

- 像素 Pibo 以 `pibo-media/source/character/states/*.svg` 为准：白色麻薯身体，没有深色描边；深灰点眼和眉点；灰色双瓣鼻吻；浅灰 U 形手；白色脚凸。
- 头顶的锯齿长叶就是 `bo`，所以 `bo` 的生长就是 Pibo 身上看得见的成长。

### 经验与等级

- 健康经验 = `bo` 能量（1 能量 = 1 经验，受 `bo` 每日上限约束），从账本推导，跟随恢复和同步。
- 互动经验与每日上限：

  | 来源 | 经验 | 每日上限 |
  | --- | --- | --- |
  | 拍一拍 | 2 | 10 次 |
  | 餐食成功 | 8 | 2 次 |
  | 陪伴回答 | 5 | 3 次 |
  | 心愿 | 15 | 3 个 |
  | 流星 | 5 | 1 次 |

- 升级所需经验为 `50 + 25×(L−1)`，单级封顶 400，最高 30 级。
- 外观解锁：身体三档；叶子依次长长、双叶、花苞、开花；配饰有围巾、橡果帽、背包、夜光叶；另有伸懒腰、数石头、哼歌、打滚四个小动作。

### 熟悉度与语气

- 熟悉点 = `相处天数×10` + 互动点，只增不减，分 10 颗心。
- 语气档：0–2 心是 `gentle`，3 心起是 `tease`（吐槽），6 心起是 `oldFriend`（互损）。
- 文案单元可标 `minTone`，平台只做过滤。

### 今日小心愿

- 每天 3 个，用日期种子挑选。
- 步数和活动目标按 14 日个人基线夹取：步数 3000–12000，活动 15–60 分钟。没有健康数据时换成照顾类心愿。
- 20 点后出现睡眠心愿，第二天早上用真实睡眠判定。
- 没有惩罚、连续天数或催促通知。

### 装饰目录

- 共 10 件，价格与等级要求在 Core：蘑菇凳、名牌、石头堆、花圃、风车、月亮灯、小池塘、秋千、篝火、帐篷。
- 花圃、风车、月亮灯分别显示今天的步数、活动和昨晚的睡眠；名牌显示相处天数；石头堆随 056 的石头小事变高。
- 吊床和观测仪保持原流程。

### 及时反馈

由一条串行队列播放，不与气泡、弹层、陪伴提问重叠：
- 离开摘要（主导来源）、前台来源火花、`bo` 进度；
- 升级揭晓、心愿盖章、多一颗心或解锁语气档；
- 拍一拍上限（每天说一次）；
- 早晨睡眠一句、相处纪念日（7／14／30／50／100／200／365 天）；
- 夜空流星、摇一摇、运动模仿。

触发条件全部由 Core 判定。

### 吐槽边界（修订 034）

- 可以吐槽数字本身和 Pibo 自己。
- 不催促（034 第 9 条继续有效）、不制造愧疚、不评价身材体重、不和他人比较、不下医学判断（034 第 10 条继续有效）。
- 数字放在气泡的事实小字里，不写进句子（沿用 055）。
- 以上由 HarmonyPibo 的 `tools/test_growth_copy.mjs` 与 `tools/test_pibo_pat_conversations.mjs` 强制。

### 本轮不做

每日像素拍立得（Core 已提供 `polaroidDue`）、甲虫痕迹、角落按钮与气泡的像素皮肤。

## 当前状态

方向已批准。HarmonyOS 初版已实现：`pibo-core 0.28.0`，HarmonyPibo `feature/pixel`。自动化与 HAP 构建通过，**尚未真机验证**；切片判定的 5 人测试、帧率和耗电都未执行。实施记录见 HarmonyPibo `docs/harmony-first/2026-10-19-像素化重构.md`。iOS 冻结中，补齐清单在该记录第 7 节。
