# 决定 014：既有物件解锁序列与风铃植物修正

> 决定日期：2026-07-28  
> 状态：已拍板；修正决定 013 中的物件称呼与未经确认的消费假设

## 现有三个物件

用户提供的现有设计中包含三个彼此独立、逐渐解锁的内容：

1. 睡眠窝；
2. 悬挂的灯；
3. 风铃植物。

不得再把悬挂的灯与风铃植物合称为“风铃灯”。后续叙事与产品文档统一使用各自名称。

## 与既有解锁计划的关系

- 三个物件本来就是产品计划内的渐进解锁内容；
- 故事直接借用既有解锁顺序，不另外发明一套物件获取系统；
- 当前没有确认风铃植物必须消耗“一枚 `bo`”，因此故事基础不写死具体价格；
- 是否消耗 `bo`、消耗多少、各物件的解锁阈值属于后续产品机制设计。

## 故事功能

- 睡眠窝首先让共同空间具备休息功能；
- 悬挂的灯让空间从临时停留处逐渐变成可以生活的地方；
- 风铃植物在前两个实用物件之后出现，它对取火和返航没有直接帮助，因此最适合承担“非任务价值”的关系意象。

风铃植物的关系弧保留：

1. 它按照既有计划解锁并进入共同空间；
2. Pibo 最初无法理解它对任务有什么用；
3. Pibo 后来在没有奖励和请求时主动调整或照看它；
4. 返航前，Pibo 停下来听它完成一次声光或风动变化；
5. Pibo 离开后，风铃植物留下，成为共同记忆。

## 对决定 013 的修正

决定 013 中以下内容不再适用：

- “风铃灯”这一混合称呼；
- “用户固定消耗一枚 `bo` 解锁风铃灯”的未经确认规则；
- 把风铃植物描述成单独新增的主线物件。

决定 013 其余内容继续有效：二十一个事件整体方向、非任务物件的关系功能，以及结尾的延迟自动记录。
