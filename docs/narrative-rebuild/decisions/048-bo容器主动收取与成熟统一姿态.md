# 决定 048：bo 容器主动收取与成熟统一姿态

决定日期：2026-09-07。状态：用户已批准；HarmonyOS 先实施，iOS 后续补齐。

替代 032/046 中“成熟 bo 直接投入、禁止拔取、发现后不自动 Half Sheet”的对应条款，其余成本、顺序、能力与基础功能免费边界不变。

- bo 是留在头顶的充能容器。未满可点击和轻微拖拽，但任何拉动都不能收取；充满为实心能量。
- 头顶最多展示一枚成熟 bo，未收取一直保留；后续健康能量暂存不丢失，收取后继续下一枚充能。旧版多枚成熟资产保留、逐次收取，不自动转余额或丢弃。
- 用户向上拉，根部始终与头顶连接。第一阈值给临界反馈，继续拉到第二阈值才收取内部能量；容器不脱落，能量飞入常驻余额。阈值前松手回弹，不入账。
- 常驻余额只显示已收取且可消费的 bo。共同物件只能消费该余额，未收取资产不能直接消费。
- 成熟后统一正常站姿作为表现覆盖，健康主状态不改；只需一套拉取表情与动作。收取结束恢复当前真实状态对应表现。根部和角色动作使用相同变换，不脱接。
- 动作包括抬眼、跟手伸展、轻抬手、临界期待、释放眨眼、追随能量和回正；声音与触觉配合临界、释放和入账。Reduce Motion 保留可理解反馈。
- 真实成熟且未收取时，本地通知提醒一次；不连续催促，不按预计成熟时间制造事实。收取后撤销，点击回到森林不自动收取。系统未交付健康数据时不承诺后台精确成熟提醒。
- 初始只显示一个灰态目标。当前物件唤醒完成后，展示下一目标显影，再自动打开功能 Half Sheet；用户关闭后不反复弹。后台/浮层打断在安全首页恢复，不同时播放多段。
- 物件命中排除透明像素；与 Pibo 拍一拍区域分开。身体双击与头顶拖动分别处理。

跨平台规则先发布 Core 正式版本；HarmonyOS 与必要服务端适配随后完成。iOS 本轮不实现表现层，也不要求同轮升级 App 精确依赖。Core 内 Swift ABI 包装随 SDK 发布属于合同维护，不代表 iOS App 已补齐。
