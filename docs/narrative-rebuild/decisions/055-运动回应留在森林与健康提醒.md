# 055：运动回应留在森林与健康提醒

日期：2026-09-28。状态：用户已批准方向（「实现，先实现鸿蒙端」），HarmonyOS 先行，iOS 按 Harmony-first 记录补差。批准依据：用户确认两件事——成就弹窗换成森林里的回应；HRV 提醒新安装默认关、不推偏高、当天不重复。

## 背景

- 一次运动之后，Pibo 被挪进一张卡片，必须点「确定」才能关；同一件事还被系统横幅和锁屏实时活动各说一遍。这个弹窗来自 7 月底的工程规格，不是编号决定。
- Core 只认结束 5 分钟内的运动。鸿蒙只在前台读运动，所以 App 没开着时做的运动，回来后基本得不到回应。
- HRV 提醒默认打开、藏在「消息通知」下面，文案是「这次 HRV 低于当前参考范围。已记录。」——「已记录」是决定 034 点名的程序感用词；「高于参考范围」其实只是高于个人均值，约一半读数都会落进去，推出去像打分；持续偏低每 2 小时再推一次。

## 决定

### 运动回应留在森林里

- 回到首页时，Pibo 在原地演一次运动庆祝（走满 8,000 步演 muscle），气泡说「你动起来以后，我这里也有了变化。」，气泡下一行系统小字写事实（如「跑步 · 30 分钟」「今天 8,000 步」）；随后是 `bo` 生长反馈和状态说明。
- 全程约 7 秒，零点击：点 Pibo 或气泡可以提前结束，打开任何浮层也会结束；错过不丢任何东西——`bo` 与状态照常计入。
- 一次运动只回应一次，在它结束的那个本地日内，不论多晚打开 Pibo；Pibo 开始观察之前（首次引导完成前）结束的运动属于历史，不回应。同一批里有多次运动，只回应最新的一次。睡着时不演，跨日作废。
- 回应不是奖励，不加连续天数、不给额外 `bo`（决定 043、046）。
- 不再有成就弹窗，也不再为运动发锁屏实时活动。

### 通知只说一遍，而且只在被选择时说

- App 在前台时不为运动或 `bo` 发系统横幅：答案已经在森林里。鸿蒙只在前台读取运动，因此不发运动通知；iOS 仅在后台送达时保留运动通知。
- `bo` 成熟通知（决定 048）只使用用户已经给过的通知权限，成熟本身不弹系统授权框（决定 049）。第一枚成熟 `bo` 只由 Pibo 在森林里说一句，不另发通知。

### HRV 变化提醒

- 设置里单列「HRV 变化提醒」，写明会提醒什么。新安装默认关，打开时才请求通知权限；老安装保留原「消息通知」开关的实际取值，只把名字改清楚。
- 只在一次确认读数比个人平时低（注意／超载）时说一次，当天不重复；当天推过偏低、之后回到平时（正常／优秀），再说一次「回到平时」。偏高（优秀）永不推送。夜间 23:00–7:00 不推；「回到平时」距上一条至少 10 分钟。以上规则由 Core 决定。
- 文案按决定 034：看到了什么 → 怎么理解，不写数字、档位、建议，保留不确定：
  - 偏低：「这次 HRV 比你平时低一些，我先不下结论。」（注意与超载同一句：超载也可能来自静息心率偏高，「低不少」会多说。）
  - 回到平时：「HRV 回到你平时的样子了。」
- 点提醒打开健康记录并滚到当天压力卡；压力卡上的「参考范围」改为「你平时」。
- 「每次测到 HRV 都推」只保留在调试版。

## 对既有决定的关系

- 不改变决定 048 的成熟通知语义，只收紧授权方式；不改变决定 002 的健康事实边界：系统小字给事实，Pibo 不做医疗判断。
- 本决定不新增场景、物件或动画批次（决定 051）：运动庆祝与 muscle 素材已存在，只是从卡片移回森林。

## 平台顺序

本决定 → `pibo-core 0.25.0`（运动回应资格、HRV 变化提醒规则）→ HarmonyPibo 子模块与平台实现 → HarmonyPibo `docs/harmony-first/2026-09-28-*` 记录 → iOS 精确 Swift Package 版本与表现补差（含：iOS 改用 Core 运动表演选择、前台不弹运动横幅、实时活动移除或改写、HRV 设置迁移与点击去向）。
