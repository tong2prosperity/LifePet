# 052：六状态五变体与场景表演

2026-09-09。用户明确授权：在 pibo_design 先设计、规划，再实现并集成；每状态五种区别明确、合理的动画和表情，每次新状态随机选择，可以在场景不同位置。用户补充：motion-design 仅可作为制作规范，不得作为创意参考或限制创造力。此项为决定 051 的显式范围例外，不恢复其他延后功能。

- 当前六个 Core 主状态各五种表现，共 30 段。不将历史美术姿态扩成新的健康状态。
- 先创作具体行为、分镜与表情，再处理技术。允许有性格的夸张、跳跃、手舞足蹈、滑坐和喜剧停顿；状态含义仍然可读。睡眠保持睡眠，等待数据不演成生病。
- 进入新的健康状态时选择一次；同状态刷新、页面重绘、拍击和餐食观察不重新抽取。Core 消费平台熵并返回变体；有效前次选择在下一状态抽取中排除，同状态保留。无后台定时抽样。
- 表演位置由资源／平台森林布局承载，睡眠必须有承托，有吊床所有权才能使用吊床。身体与 bo 的手势命中随呈现更新。
- `bo` 成熟收取统一站姿、特殊 resting／recovering、食物观察和拍击的已有规则保留。减弱动态使用可识别静态姿态；后台停止绘制。
- 设计计划、30 段源分镜及离线审阅位于 `pibo_design/state-variants-v6/`。代码完成、媒体输出和设备验收分别记录，不将设计稿当作已验收 App。
- HarmonyOS 先集成，iOS 表现层本轮不修改，按 Harmony-first 后补齐。跨平台随机规则必须先发布 Core 正式标签。

2026-09-09 用户审阅纠正：Pibo 没有嘴，角色设计及双端资源不得添加嘴。主状态严格来自 Core `PiboState` 的 dataUnknown/sleeping/waking/stable/energetic/tired；同状态的五段必须在静态轮廓、支撑关系和动作意图上可辨识，不以轻微表情、速度或落点差异充数。v6.1 据此重做。
