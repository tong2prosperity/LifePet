# 决定 044：拍一拍动作与文本冷却解耦

> 决定日期：2026-08-26  
> 状态：已确认并进入双端实现  
> 替代范围：决定 033 与上下文动作设计中“冷却期整次点击无动作、无触觉”的条款

## 决定

一次在 Pibo 身体上的有效双击包含两个彼此独立的结果：

1. **物理回应**：每次都立即触发 Core 当前主状态对应的短视觉动作和轻触觉，没有冷却；
2. **文本机会**：仍受三秒文本冷却控制，只有冷却外才选择和显示一句文本。

单击仍然不形成拍一拍。VoiceOver 的一次辅助功能激活继续等价于一次有效双击。

## 冷却内行为

文本冷却内的有效双击仍然重播动作与触觉，但不得：

- 替换、撤下或延长当前气泡；
- 推进微章节、记录游标或首次接触序列；
- 消费健康事件 token；
- 改变 `resting`、`greeted` 等行为快照；
- 重复打开健康状态页面或执行其他外部副作用；
- 进入旧 Pat V2 的次数、生气、概率或排队逻辑；
- 产生 `pat` 文本互动埋点。

动作播放中再次双击时，平台取消当前短动作、恢复规范姿态并立即重播，不叠加、不排队。Reduce
Motion 使用已有的缩减动作，但不能取消本次可见确认。

## 规则与平台边界

- Core 继续拥有六状态到 `checkConnection / letSleep / morningGreeting / checkIn / play / rest`
  的动作映射，以及文本冷却时长和判断。
- Core 的三秒接口明确命名为 `speechCooldownDurationSeconds` 与 `speechCooldownAllows`；旧名称仅作
  ABI 兼容，不再代表整次拍一拍资格。
- iOS 与 HarmonyOS 先播放平台动作／触觉，再请求文本解析；文案缺失或目录加载失败不能阻塞物理回应。
- JSONL 的 `action` 继续描述文本单元的语义和首次副作用资格，但不再决定本次物理拍击能否播放动作。
- `pat` 埋点保持历史口径，只记录真正显示文本的互动。

## 实现检查点

`pibo-core 0.15.1` 已增加文本冷却专用 ABI 并保留旧接口兼容。双端消费同一版本后，应以连续
双击专项测试固定“动作／触觉每次发生，文本三秒内只发生一次”的行为。
