# 决定 046：共同物件渐进解锁、能力与发现反馈

> 决定日期：2026-08-28  
> 状态：已拍板；共享 Core `0.18.1` 与 HarmonyOS 已实现，iOS 表现层待对齐  
> 修订范围：替代决定 032 中过时的物件顺序、价格、补梦风铃／铃兰灯能力映射及“首次出现动画待定”状态；不改变决定 043 的免费 Shadow Pibo 基础关系，也不改变决定 045 的准备度计算合同。

## 成长链与成本

共同物件按一条固定成长链进入森林：**吊床 → 状态观测仪 → 补梦风铃 → 铃兰灯**。对应的单件成本为：

| 顺序 | 物件 | 需要的成熟 `bo` | 累计 `bo` |
| --- | --- | ---: | ---: |
| 1 | 吊床 | 1 | 1 |
| 2 | 状态观测仪 | 3 | 4 |
| 3 | 补梦风铃 | 6 | 10 |
| 4 | 铃兰灯 | 10 | 20 |

现有经济合同约为每日 `0.6–1.3 bo`，因此该曲线让吊床快速教会用户投入，同时让后续物件逐步形成几日到数周的期待。价格、目录顺序和 prerequisite 只由 `pibo-core` 定义，平台和服务端不得另建一套产品常量。

## 首页只显示一个新目标

- 首页同时显示全部已拥有物件，以及 Core 目录中唯一的下一个未拥有物件；
- 更后面的未解锁物件不渲染、不进入无障碍遍历，也不能通过目录预览；
- 当前灰态物件本体是唯一的检视与投入入口；不恢复背包、拔取、独立奖励窗口或多目标陈列；
- 已拥有后期物件但缺少新前置的旧用户，仍永久保留所有权和新能力；不回收、不降级、不重复扣除 `bo`。

## 四件物件的真实能力

### 吊床：休息落点

- 开放最近一次睡眠回顾，以及用户授予通知权限时的睡醒通知；
- Pibo 只在 Core 主状态为 `sleeping` 或 `tired` 时可以自主使用吊床；
- 首版不增加用户手动命令 Pibo 休息的入口；定时陪伴休息留待独立决定。

缺少睡眠数据或拒绝通知不影响物件所有权。

### 状态观测仪：理解当下与近期变化

- 保留决定 045 的首页今日准备度常驻卡、Core 依据、校准进度和缺失数据语义；
- 新增最近 7 个自然日的准备度趋势和已保存的主要原因；
- 缺失的日期显示为空缺，不使用插值、平滑或上一天数值冒充；
- 不把原始 HRV、心率、步数或热量堆成新的健康仪表盘。

准备度的数值、分段和原因仍只由已发布 Core 产生；平台只展示日快照。

### 补梦风铃：散步回声收藏

- 从已完成的散步涂鸦记录中选择一条作为当前回声；
- 可以查看、替换、清除并在森林中重播这条路线；
- 没有散步记录时显示中性空状态，并可前往始终免费开放的散步涂鸦；
- 只持久化当前 Pibo 身份下的稳定记录 ID，不复制路线几何；原记录被删除时安全清除引用；
- 收藏和重播不产生 `bo`、积分、连续天数或奖励。

基础餐食相机与散步涂鸦的创作、保存、历史始终免费，不受风铃 entitlement 门控。

### 铃兰灯：森林共光态

- 用户可以逐盏点亮铃兰，点灯状态在天亮时失效，不增加手动熄灯；
- 第一盏灯为本地灯下微光与水面反射；第二盏把光扩展到附近叶片并调整环境声景；第三盏让整片森林进入共光态，持续到天亮；
- Pibo 可以在夜间靠近灯下停留，但不在没有批准素材时手画专用动作；
- 解锁铃兰灯后只在一次性预览中播放 `2.4 s` 森林全局光波，随后回到当前真实点灯数量；
- 好友来光在已拥有铃兰灯时只附加一次克制的色彩脉冲，不产生新奖励或关系数值。

Shadow Pibo 的邀请、接受、映照、同步、送光和退出管理仍是免费基础能力，不检查铃兰灯所有权。“在灯下保留好友快照”不进入首版。

## 新目标的“静默显影”

当当前物件完全落位、解锁层关闭且首页回到无 overlay 的安全状态后，新的 next target 执行一次“静默显影”：

- 等待 `500 ms`，再用 `720 ms` 从 opacity `0 → 0.42`、scale `0.94 → 1`；
- 缓动为 ease-out quart，近似 `cubic-bezier(0.165, 0.84, 0.44, 1)`；
- 物件背后的基础青绿径向微光只上升再消退一次，在中点一次轻触觉；
- 不播放声音，不移动相机，不使用粒子、弹窗、红点、循环闪烁或奖励窗口；
- 完成后才按 Pibo 身份提交 discovery checkpoint；中途进后台或被 overlay 打断则下次安全进入时重播；
- 首次安装的吊床可静态出现，不把初始页面当作解锁成功。

Reduce Motion 下直接显示最终灰态，只做一次无障碍播报；不缩放、不发光、不触觉。新物件不强制移动辅助技术焦点。

## Debug 动画实验室

双端 Debug 构建必须提供可重复预览能力：HarmonyOS 放在设置的 `DEV`
区，iOS 放在现有 Home Debug overlay。

- 可选“自动下一件”或指定四件中的任意一件；
- 可选 System、Full Motion 或 Reduce Motion；
- 可预览新目标静默显影，也可预览铃兰灯 `2.4 s` 解锁光波；
- 必须调用生产用的同一动画控制器，不维护 Debug 专用动画副本；
- 预览不持久化所有权、`bo`、discovery checkpoint 或点灯状态，不调用后端，不产生分析事件；
- Release 构建不存在该入口或代码路径。

## Core 与兼容合同

- 保持物件稳定 ID：`Hammock = 0`、`Chime = 1`、`Lantern = 2`、`StatusObserver = 3`；只调整目录顺序和 prerequisite；
- 能力映射为 `Hammock → SleepReview + WakeNotification`、`StatusObserver → RecoveryStatus`、`Chime → WalkEchoCollection`、`Lantern → LanternLighting`；
- `WalkEchoCollection` 只能作为新的尾部能力 ID 添加；旧 `DewCamera`、`WalkDoodle`、`ShadowPiboEligibility` 枚举值为 ABI 兼容保留，但不再由共同物件授予；
- 已拥有补梦风铃的旧用户自动获得散步回声收藏，已拥有铃兰灯的用户保留点灯和共光能力；
- 服务端交易校验与 Core 同步为 `1 / 3 / 6 / 10`、同一 prerequisite 链、原子且幂等；旧所有权永远先于新前置检查。

## 明确不做

- 用手动休息或定时陪伴填充吊床首版；
- 对 7 日准备度空缺进行插值或健康推断；
- 用风铃解锁散步涂鸦创作或基础餐食相机；
- 用铃兰灯解锁 Shadow Pibo 资格，或在灯下长期保留好友快照；
- 为首次发现增加声音、相机运动、粒子、循环吸引或自动 Half Sheet。
