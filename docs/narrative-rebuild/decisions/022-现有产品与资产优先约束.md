# 决定 022：现有产品与资产优先约束

> 决定日期：2026-07-29  
> 状态：已拍板  
> 盘点依据：[`../19-现有产品叙事承载盘点.md`](../19-%E7%8E%B0%E6%9C%89%E4%BA%A7%E5%93%81%E5%8F%99%E4%BA%8B%E6%89%BF%E8%BD%BD%E7%9B%98%E7%82%B9.md)

## 基本原则

- 新叙事产品架构必须向当前已经实现的 App、UI、功能和动画资产贴合；
- 已投入制作的森林主页、角色、动画、健康功能、足迹和现有呈现结构，非必要不做大改；
- 允许为承载故事做小范围增补和状态改造，但不默认新建平行架构；
- 每项新增页面、入口或复杂交互都必须证明现有结构无法承载同一核心内容。

## 保护资产，不保护旧叙事含义

- 视觉资产、动画、交互手势、功能能力和稳定代码缝隙优先复用；
- 与新故事冲突的旧世界观、台词、触发条件和伦理逻辑不得因为已经写进代码就继续沿用；
- 优先采取“保留资产与交互，替换触发和含义”的迁移方式。

## 当前默认方向

- 主页继续是固定森林 SpriteKit 舞台；
- 初版保留餐食相机、Walk Doodle、足迹、设置与健康相关入口；具体主页布局在产品设计阶段贴合现有结构处理；
- 现有小游戏工程资产不等于初版产品范围：除 Walk Doodle 外，其他游戏暂不进入初版；
- 故事提示优先使用主页动作、气泡、环境和现有弹层；
- Onboarding 可以按照新的相遇与授权故事重构，不受当前旧流程约束；其中现有视觉组件和授权能力仍可复用；
- 第一枚 `bo` 优先复用现有能量特写与拔取资产，但必须在真实日常健康数据积累后于正式主页发生；
- 故事回看优先研究接入现有足迹或复用已有但未接入的故事日记缝隙，不默认新增第五个主页入口；
- 具体复用方案仍需逐项确认，不能把本方向误写成已经完成的 UI 设计。
