# 决定 071：iOS 全量像素对齐与腕上账本边界

> 日期：2026-10-23
> 状态：已批准。用户要求「对齐鸿蒙 pibo 的像素化的所有功能，并在对齐过程中，发现不合理的地方你可以修改，你有决策权」。
> 本决定修订 057–070 中「iOS 不补齐」的平台范围；不恢复已移出路线图的功能。

## 一、对齐范围

iOS 的森林、六状态角色、成长外观、bo 头叶、日程、邀请、探索收藏、生活回声与变形、两季剧情、陪伴记忆、今日心愿、装饰购买、拍立得、足迹、相机、餐食样本、读数报告、设置、首启、分享、桌面组件和腕上陪伴，采用鸿蒙当前像素主线的功能与语义。Core 继续拥有确定性规则；iOS 精确固定正式标签，不移植阈值。

像素是唯一可达表现；旧表现启动参数与小游戏调试旁路退役。隐藏功能的权属、余额、好友关系和历史不删除。系统权限、相册、通知、分享和表冠滚动仍使用平台能力。正文和健康图表优先保证可读性。

## 二、修正已有断点

- 未完成的提问心愿在双击时优先直达正式选项；思考气泡服从当天心愿、可选提问、Core 每日配额和忽略退避；睡眠、遮挡与已在回答时不亮。
- 预设回答与自定义回答都只在正式提交成功后进入成长计数，立即重判心愿；重复回调不重复奖励。
- 季节剧情使用 Core 陪伴注意力预算，并在等待时让普通返家对白让位；小事连载、共同的第一次和答案回响与足迹记忆接通。
- 装饰购买使用先记日志、账本幂等扣款、再写权属的恢复流程。未发生真实扣款的日志不授予装饰。
- 日记与拍立得链接落到对应日期；保存路径随容器迁移恢复；昨日活动数字不在今日桌面组件中继续展示。

## 三、Apple Watch 取舍

- 88×88 像素舞台复用手机的纯绘制代码；前台最高 10fps，息屏、后台与减弱动态停止连续绘制。
- 手机投影真实成长外观、余额、成熟容器、变形、当天心愿和 Core 探索站点。旧 v1/v2 快照继续可读；跨日保留身份与成长，撤下过期每日事实；新宠物不继承旧宠物投影。
- 成熟 bo 点击或上拉通过手机签发的容器 token 请求同一个真实账本，手机确认后更新两端。重复请求不能收取下一枚容器；离线保留成熟 bo 并说明连接后再收，不创建手表独立余额。
- 双击为腕上动作、简短反馈与卡住解救；单击不推进文本。腕上反馈不伪装成手机长对话进度，也不凭点击生成健康收益。
- 小心愿展示手机真实盖章，步数进度可读取手表 HealthKit 的真实活动。离线缺少手机语义时不在 Swift 复制 Core 的健康状态阈值，不凭空完成心愿或生成探索收藏。

## 四、匿名统计

对齐当前鸿蒙事件及属性白名单。不上报健康数字、状态原因、照片、自由输入或账号标识；退役功能事件被门面拒绝。设置提供「使用情况统计」开关，Debug 默认不发生产统计。底层仍使用已有 DataSneaker 批量管线，不在绘制与连续传感器回路打点。

## 五、验证

实施与验证证据统一记在 `docs/pixel-ios-parity.md`。真实 HealthKit、物理相机、触觉、配对设备同步时延和长期耗电不能以模拟器检查代替。
