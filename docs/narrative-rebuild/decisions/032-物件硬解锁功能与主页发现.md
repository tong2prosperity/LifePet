## 物件与能力映射

四件 `bo` 物件不仅改变共同空间，也真实开放对应产品能力：

| 物件 | 解锁能力 |
| --- | --- |
| 吊床 | 每日睡醒后的通知与睡眠回顾行为 |
| 补梦风铃 | Walk Doodle；露珠相机的后续增强价值待单独设计，基础餐食相机不受此门控 |
| 状态观测仪 | 根据睡眠和身体数据推算的恢复状态 |
| 铃兰灯 | 当前保留魔法点灯；作为 Shadow Pibo 的入口与投影载体，但不再硬解锁基础好友连接 |

价格、顺序、前置和消费继续由 `pibo-core` 统一定义。

## 采用真正的功能硬解锁

- 正式推翻“首发功能从开始使用后全部可用、不以物件为门槛”的旧规则；
- 用户未解锁对应物件时，除已明确拆出的基础餐食相机外，相关功能不可使用；
- 未解锁功能的独立入口不提前出现；但首页会把唯一的“下一个物件”本体以灰态放在森林中，作为检视入口；
- 解锁页必须提前说明每件物品会开放什么能力，让期待来自明确收益，而不是 `???`。

健康授权、原始健康记录和形成 `bo` 所必需的基础能力不属于这四项功能门控，不能因
物件未解锁而中断。具体哪些历史健康展示属于基础层，留到工程迁移清单中逐项确认。

## 森林内检视与解锁后的发现方式

- 首页只展示一个灰态的下一个物件，不并列展示四项，不另设目录或进度窗口；
- 点击灰态物件打开轻量 Half-sheet，明确说明功能、成本、当前库存和不足原因；
- 解锁后同一个节点直接恢复正常状态，Core 顺序中的下一个目标再以灰态进入森林；

- 物件解锁成功后，不从解锁页直接把用户送入新功能；
- 用户返回主页，先看到物件进入共同空间，再发现随之出现的新入口；
- 物件变化和入口出现共同构成解锁反馈；
- 解锁页不使用“去使用”作为主要结束动作；解锁成功后提供「回到森林」，由用户
  主动返回主页发现变化。

四件物品采用以下入口方式：

- **吊床**：吊床本身可点击，进入睡眠回顾；睡醒通知在满足数据与系统权限时自动生效；
- **补梦风铃**：当前实现中解锁后出现 Walk Doodle 入口；基础餐食相机从首日开始独立可用；
- **状态观测仪**：不再作为长期佩戴在 Pibo 软体身体上的挂件，改为放置在森林中的
  可点击物件；点击后弹出恢复状态 Modal；
- **铃兰灯**：保留现有点灯互动；不再开放 Walk Doodle。它与未来 Shadow Pibo
  单好友连接关联；基础好友连接免费，不能因物件未拥有而阻断邀请或接受。Shadow 尚未进入
  工程版本前仍不开放社交入口、不显示不可用占位功能。

物件具体坐标、入口图形和首次出现动画仍在视觉设计阶段确定。

## 数据不足不阻止拥有物件

- 没有手表、权限不足、缺少睡眠 / HRV / 心率等数据时，用户仍可正常解锁并永久拥有物件；
- 能力页面必须诚实显示“等待数据”“正在校准”或同类状态；
- 不得伪造恢复分数，也不得把缺少设备解释成用户失败；
- 物件状态与能力状态分开：物件可以已解锁，而能力仍在等待数据。
- 用户拒绝通知权限时，吊床仍提供 App 内睡眠回顾，只关闭系统睡醒通知；物件介绍
  必须提前说明这一差异。

## 物件检视 Half-sheet 信息规则

- 不再提供可浏览所有物件的「共同物件」页面；
- 当前灰态物件完整展示名称、图片和解锁能力，不使用 `???`；
- 内容先说明「唤醒后获得」及必要数据 / 权限，再显示准确成本与库存；
- 唤醒后关闭 Half-sheet 并回到同一个森林，不直接跳入功能；
- 吊床介绍必须明确：解锁睡眠回顾；有通知权限时还会在每天睡醒后发送通知，拒绝
  通知不影响 App 内查看。

## 补梦风铃与餐食相机

“露珠形成图像接收器”可以保留为未来高级相机能力的叙事连接：风铃末端凝结的露珠
能够聚拢光线，帮助 Pibo 理解图像；它不声称风铃代替手机摄像头拍摄。首版基础餐食
相机已明确从这条门控拆出，因此用户没有风铃也能从右上角按钮拍摄和保存餐食。

该连接可继续沿用「露珠相机」名称。最终物件说明和解锁事件台词在 UI 方案确认后
统一修订。

截至 2026-08-17，产品确认不增加新物件。补梦风铃在当前 MVP 中继续承载 Walk
Doodle；高级餐食观察、投影或持续服务价值单独重新设计。在该设计批准前，检视
Half-sheet 不宣称唤醒风铃才能使用基础相机，也不宣称一次获得两项现成功能。

## 铃兰灯与未来 Shadow Pibo

- 铃兰灯具有魔法属性，现有逐盏点灯是当前可交付互动；
- 未来可通过它建立一条单好友连接，让好友的 Pibo 以颜色更淡、不同颜色或半透明的
  Shadow Pibo 形式出现在用户主页；
- 用户通过 Shadow Pibo 的当前表现，只能大致感知好友状态，不能宣称读懂好友真实
  心情、做医疗判断或暴露精确健康数据；
- Shadow Pibo 的双向单好友关系、近似实时状态同步、最近快照回退、回光和隐私退出边界
  已由决定 043 冻结；它仍不自动进入当前 P0，不得在未排期时提前显示空壳入口；
- 基础连接免费开放。接收邀请不得要求用户先拥有铃兰灯或消费 `bo`；铃兰灯承担叙事入口和
  投影载体，而不是社交资格门槛；
- 既有魔法点灯 entitlement 暂不自动免费。基础投影入口与点灯 entitlement 在同一物件上的
  视觉分层进入 Shadow UI 设计；
- 已经拥有铃兰灯的用户保留现有能力，未来不需要为 Shadow 再次消费 `bo`。
