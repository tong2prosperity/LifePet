# 决定 032：物件硬解锁功能与主页发现

> 决定日期：2026-08-06
> 状态：已拍板
> 替代范围：修正决定 013、015、018 及主线大纲中“物件不解锁能力、首发核心功能从开始即可使用”的旧规则
>
> 2026-08-07 修订：补梦风铃一次解锁露珠相机与 Walk Doodle，不增加新物件；
> 铃兰灯保留魔法点灯，并与未来 Shadow Pibo 能力关联。工程不得继续实现旧的
> “铃兰灯 → Walk Doodle”映射。

## 物件与能力映射

四件 `bo` 物件不仅改变共同空间，也真实开放对应产品能力：

| 物件 | 解锁能力 |
| --- | --- |
| 吊床 | 每日睡醒后的通知与睡眠回顾行为 |
| 补梦风铃 | 露珠相机与 Walk Doodle，两项能力一次解锁 |
| 状态观测仪 | 根据睡眠和身体数据推算的恢复状态 |
| 铃兰灯 | 当前保留魔法点灯；未来解锁 Shadow Pibo 单好友连接 |

价格、顺序、前置和消费继续由 `pibo-core` 统一定义。

## 采用真正的功能硬解锁

- 正式推翻“首发功能从开始使用后全部可用、不以物件为门槛”的旧规则；
- 用户未解锁对应物件时，相关功能不可使用；
- 未解锁功能的入口不提前出现在主页，避免主页堆放禁用按钮；
- 解锁页必须提前说明每件物品会开放什么能力，让期待来自明确收益，而不是 `???`。

健康授权、原始健康记录和形成 `bo` 所必需的基础能力不属于这四项功能门控，不能因
物件未解锁而中断。具体哪些历史健康展示属于基础层，留到工程迁移清单中逐项确认。

## 解锁后的发现方式

- 物件解锁成功后，不从解锁页直接把用户送入新功能；
- 用户返回主页，先看到物件进入共同空间，再发现随之出现的新入口；
- 物件变化和入口出现共同构成解锁反馈；
- 解锁页不使用“去使用”作为主要结束动作；解锁成功后提供「回到森林」，由用户
  主动返回主页发现变化。

四件物品采用以下入口方式：

- **吊床**：吊床本身可点击，进入睡眠回顾；睡醒通知在满足数据与系统权限时自动生效；
- **补梦风铃**：当前实现中解锁后，固定森林主页同时出现 Walk Doodle 与露珠相机入口；
- **状态观测仪**：不再作为长期佩戴在 Pibo 软体身体上的挂件，改为放置在森林中的
  可点击物件；点击后弹出恢复状态 Modal；
- **铃兰灯**：保留现有点灯互动；不再开放 Walk Doodle。它与未来 Shadow Pibo
  单好友连接关联，但当前不开放社交入口、不显示不可用占位功能。

物件具体坐标、入口图形和首次出现动画仍在视觉设计阶段确定。

## 数据不足不阻止拥有物件

- 没有手表、权限不足、缺少睡眠 / HRV / 心率等数据时，用户仍可正常解锁并永久拥有物件；
- 能力页面必须诚实显示“等待数据”“正在校准”或同类状态；
- 不得伪造恢复分数，也不得把缺少设备解释成用户失败；
- 物件状态与能力状态分开：物件可以已解锁，而能力仍在等待数据。
- 用户拒绝通知权限时，吊床仍提供 App 内睡眠回顾，只关闭系统睡醒通知；物件介绍
  必须提前说明这一差异。

## 解锁页信息规则

- 页面正式命名为「共同物件」，替代偏商店语气的「兑换道具」；
- 所有未解锁物件都完整展示名称、图片和解锁能力，不再使用 `???`；
- 展开内容先说明「解锁后获得」及必要数据 / 权限，再展示词典式物件说明；
- 解锁后展示「回到森林」，不直接跳入功能；
- 吊床介绍必须明确：解锁睡眠回顾；有通知权限时还会在每天睡醒后发送通知，拒绝
  通知不影响 App 内查看。

## 补梦风铃与餐食相机

接受“露珠形成图像接收器”的连接：风铃末端凝结的露珠能够聚拢光线，Pibo 据此
做出最初的图像接收器，并开始借助用户手机的相机理解和记录地球食物。风铃解释的
是 Pibo 为什么获得理解图像的能力，不声称风铃代替手机摄像头拍摄。

该连接可继续沿用「露珠相机」名称。最终物件说明和解锁事件台词在 UI 方案确认后
统一修订。

截至 2026-08-07，产品确认不增加新物件。补梦风铃统一承担“记录地球留下的痕迹”：
露珠聚拢光线，帮助 Pibo 理解食物影像；风铃把不可见的移动过程翻译成线条，承载
Walk Doodle。解锁页应明确说明一次获得两项能力。

## 铃兰灯与未来 Shadow Pibo

- 铃兰灯具有魔法属性，现有逐盏点灯是当前可交付互动；
- 未来可通过它建立一条单好友连接，让好友的 Pibo 以颜色更淡、不同颜色或半透明的
  Shadow Pibo 形式出现在用户主页；
- 用户通过 Shadow Pibo 的当前表现，只能大致感知好友状态，不能宣称读懂好友真实
  心情、做医疗判断或暴露精确健康数据；
- Shadow Pibo 是大型社交与隐私功能，当前只保留概念和扩展接口，不进入 MVP，
  不实现好友关系、状态同步、后端、隐私授权或空壳用户入口；
- 未来能力上线时，已经拥有铃兰灯的用户应自动获得资格，不得要求再次消费 `bo`。
