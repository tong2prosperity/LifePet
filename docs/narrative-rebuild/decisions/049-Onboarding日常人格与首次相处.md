# 决定 049：Onboarding 日常人格与首次相处

> 2026-09-07 用户在当前 HarmonyPibo review 后明确要求：“重新实现，不要使用初见人格，使用日常人格。”
> 确认范围：以日常人格重做 HarmonyOS 首次使用；iOS 表现待补齐。

## 产品方向

遵循 `docs/PRODUCT.md` 与决定 034：以真实健康数据喂养的电子宠物，首次进入也使用同一个认真、好奇、直接、有自尊的 Pibo。首启不建立一套失忆、乱码、求救、幼态依附的特殊人格。

- 复用正式森林和正式角色表现；不以黑暗、天敌、点五下给光或授权后危险消失来推动进入。
- 初次说明先让用户理解睡眠和活动影响 Pibo 的状态与成长。
- 健康数据用途与权限由系统说明；拒绝、暂缓、服务不可用、尚无记录都允许进入森林，不启动 Demo，不伪造健康恢复。
- 第一次互动发生在正式首页，提示身体双击并复用现行 Core 日常动作、中文台词与冷却。可稍后，不设任务奖励。
- 首次主动互动不紧接自动补授权弹窗；设置及之后用户主动发起的连接操作保留。
- 在互动之后轻量介绍头顶积累、成熟收取及共同物件，再提供独立可跳过的通知选择；不在健康请求时打包通知、相机、位置或麦克风。
- 基础餐食相机、散步涂鸦与足迹按现有入口自由发现，不要求在 onboarding 完成活动。

## 故事与合同边界

此次替换决定 023/029 中作为当前 onboarding 必经步骤的初见失忆说明与临时合作表演，替换决定 024 的首启通知时机。故事身份、故乡、返航与长期人物背景没有被删除。

当前发布中的临时合作事件 01–03 继续暂停。日常首启完成不冒充 `acceptTemporaryCooperation`，不写入故事许可或健康观察事实。未来恢复该故事系统时仍需明确的独立许可。

不变更当前发布的 Core 计算或账本起算合同：首启完成时间继续作为现行非临时合作模式的资格边界；仅真实合格记录按现行规则产生积累，不发首启奖励，不提前成熟。既有用户不重走引导、不重置资产。

`bo` 表现与消费以决定 048 为准：头顶永久容器成熟后主动收取到余额，物件只消费已收取余额。

## 2026-09-08 补充：先理解产品，再决定连接

用户在确认当前说明过简后，要求按 review 建议制定详细计划并实现：

- 欢迎页明确“用真实生活，养一只 Pibo”，继续保持日常人格。
- 在健康授权前增加一张系统产品说明层，三个信息区分别介绍相处（状态与身体双击回应）、成长（头顶真实能量、成熟收取、唤醒共同物件）和记录创作（餐食贴纸与营养估算、散步涂鸦路线、足迹回看）。
- 三个信息区处在同一页，不做多页功能轮播；复用森林和首页入口图标，不要求完成任何活动。
- 说明页有独立的可恢复页面进度，允许返回；不复用故事许可，不改变 Core 或账本起算合同，已完成用户不重播。
- 本补充取代上文“互动之后才介绍成长”的信息顺序：首次双击之后只需提示右上角功能入口并独立提供可选通知，避免重复讲解。跳过双击的用户也已获得产品用途说明。
- 通知权限仅在用户主动选择时请求；启动服务不得提前在欢迎页弹出授权。
- Debug 预览同步覆盖欢迎、产品说明、健康选择三屏；权限和数据隔离保持不变。

HarmonyOS 计划与证据见 `HarmonyPibo/docs/harmony-first/2026-09-08-Onboarding产品价值说明.md`；iOS 表现仍待补齐。
