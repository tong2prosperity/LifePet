# 051：单人陪伴 MVP 边界与停止条件

日期：2026-09-09。状态：用户已批准记录并继续执行隐藏。批准原话：「让这个目标记下来。然后把能隐藏的继续做隐藏，比如 shadow pibo 功能，风铃物件等。」

## 目标

交付「可以连续相处两周的单人 Pibo」。验证真实生活影响的小生命能否让人产生持续、没有负担的牵挂。先交付 HarmonyOS 小范围验证，不以两端、手表或社交同时完成为前提。

接下来只做：让 Pibo 更可感知、让核心流程更好理解、让已有行为可靠。不以功能数量或继续堆砌内容代替关系价值验证。

## 保留与 polish 上限

- 首次使用／健康授权：理解用途、允许拒绝、发现身体双击；不加剧情或教学关卡。
- 森林／六状态：主角突出、已有状态可读、切换不跳、不穿帮；不加场景或整批动作。
- 拍一拍：命中、动作、触觉、气泡协调，修突兀和错误情境；不发展聊天机器人或大规模文案库。
- 健康状态：授权、缺失、延迟明确，跨日和前台刷新正确；不增加指标、评分和健康建议。
- bo：真实生长、成熟、收取、余额、投入可靠；不加任务、签到或新货币。
- 物件：本版只展示／开放吊床和状态观测仪，观测仪后不再显影灰态目标。
- 餐食相机：拍摄、识别、返回森林、观察、历史保存与失败恢复；不加饮食计划。
- 足迹／睡眠：真实、可读、日期一致、返回顺畅；冻结云雾视觉，不加图表风格、指标或报告中心。
- 设置：保留必要权限、声音、触觉、账号与数据管理，做好安全区、读屏和减弱动态；不扩展个性化。

## 暂停与隐藏

散步涂鸦、小游戏、Shadow／邀请／送光、风铃与铃兰灯、会员购买入口、自定义形象、后续新剧情／新场景／新物件／新动画批次都不进入本版。已隐藏的功能保持隐藏。独立手表呼吸另行管理，不属于手机 MVP 门槛；iOS 按交接后补齐。

本轮以平台发布范围关闭展示、操作和 Shadow 同步，不删除账号、好友关系、物件所有权、余额或历史记录。旧用户已拥有的风铃与灯也收起表现，权属仍保留。不显示暂未开放的占位购买目标。

本次不修改 Core 全量目录、物件成本、前置、奖励、账本或服务端合同：在既有 Core next target 结果上应用本版可见性，不跳过隐藏物件解锁后续内容。若未来重排链条、改成本或变更确定性规则，必须先发布 Core 和必要服务端合同，不在平台复制规则。

本决定覆盖 043 的本版 Shadow 发布范围、046 的本版后续物件露出及 050 的风铃占位说明。保留功能的行为合同继续遵循 048、049 等最新批准决定。

## 五条验收旅程

1. 新安装 → 理解用途 → 授权或拒绝 → 森林 → 成功互动。
2. 隔天回来 → 真实数据刷新 → 正确状态 → 能查明原因；无数据不伪造。
3. 真实积累 → 成熟 → 收取 → 投入吊床 → 看到实际行为变化。
4. 拍摄餐食 → 成功或明确失败 → 返回森林 → 成功历史可再次查看。
5. 退出／后台／断网／重启／跨日之后，状态、记录和资产仍正确。

## 停止条件

只安排两轮 polish：第一轮完整走查并修复；第二轮回归收口，仅修阻断和回归。其余美化与新想法进入后续清单。

进入首批用户试用前必须：
- 五条旅程目标真机跑通，连续三天覆盖跨日和重启；真实健康及成长不可用 Mock 代替。
- 核心崩溃、卡死、无法返回、数据失真、资产丢失／重复清零。
- 5 位非开发参与者中至少 4 位无需现场教学完成首次进入、拍一拍、找到状态说明（项目自定门槛）。
- 小瑕疵有记录，不以此无限扩展重做范围。

之后两周小范围试用，只修使用故障与数据正确性；收集主动回来和具体感受，不继续添内容。
