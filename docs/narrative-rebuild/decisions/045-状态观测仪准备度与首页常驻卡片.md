# 决定 045：状态观测仪准备度与首页常驻卡片

> 决定日期：2026-08-26  
> 状态：已确认并完成共享 Core 与 iOS／HarmonyOS 双端表现实现  
> 替代范围：状态观测仪仅显示“等待数据／正在校准”的通用弹窗，以及未获批准的全屏恢复仪表盘、树纹仪表盘和普通活动数据堆叠方案

## 决定

状态观测仪展示“今日准备度”：它是今天的睡眠与夜间身体反应相对用户个人基线的综合位置，用来回答
“今天的恢复状态和平时相比怎么样”。它不是医学诊断、疾病风险、运动处方，也不是设备厂商恢复分的转录。

准备度由已发布 `pibo-core` 唯一计算。平台只负责取得真实健康数据、保存原始事实、调用 Core、持久化
带算法版本的结果并呈现；Swift、ArkTS 和 C++ 适配层不得复制阈值、权重、窗口或缺失值策略。

## 数据层级

### 生成分数的必要数据

1. 当天必须有睡眠记录；
2. 过去最多 28 天中，必须至少有 7 天与当天同类型的 HRV 基线，或至少 7 天同口径的睡眠／静息心率基线；
3. 7–13 天标为参考值，14 天起标为稳定个人基线；不足时明确显示校准，不输出分数。

HRV 优先使用夜间 RMSSD，平台只把真实类型传入 Core；不同 HRV 类型不混为同一条个人基线。心率优先使用
睡眠心率，同一次计算中不能把睡眠心率和静息心率历史混用。

### 辅助修正数据

- 腕温只作为偏离惩罚，腕温正常不能额外抬高准备度；
- 近期身体负荷只比较此前 1–7 天与此前 8–28 天的滚动周常态，当天活动不进入当天晨间准备度；
- 原始 HRV、心率、步数、热量、运动分钟和站立小时仍属于睡眠回顾或足迹，不堆进首页观测卡。

缺失数据不按 0 分处理。缺少腕温或负荷时只省略相应修正，不把“没有测到”解释为“状态差”。

## Core 0.16.0 公式

### 睡眠分量

睡眠分量 = 睡眠充足度 × 70% + 入睡规律度 × 15% + 睡眠连续性 × 15%。缺少某个辅助分量时，
只在现有分量内重新归一化；但缺少当天睡眠时不生成准备度。

### 个体生理分量

- HRV 使用 `ln(RMSSD)` 或同类型 HRV 的 28 天中位数与 MAD 稳健标准分：个人中位数对应 70 分，
  每 1 个稳健标准差变化 15 分；
- 睡眠／静息心率同样使用 28 天中位数与 MAD，但方向相反：低于个人常态提高分量，高于个人常态降低分量；
- MAD 设最小尺度，避免短期读数几乎相同导致除零或异常放大。

主体分 = 睡眠分量 × 40% + HRV 分量 × 35% + 心率分量 × 25%。HRV 或心率只要一个达到个人基线要求即可
生成分数；缺少的生理分量在现有权重内归一化。

### 只减不加的修正

- 腕温偏离超过个人常态 1 个稳健标准差后开始扣分，最多扣 8 分；
- 近期负荷高于个人滚动常态 0.75 个稳健标准差后开始扣分，最多扣 8 分；
- 近期负荷只以“低于平时／与平时相当／高于平时／正在校准／数据不足”呈现，不暴露内部 z 值。

最终区间固定为：`<55 明显偏低`、`55–69 低于个人常态`、`70–84 个人常态`、`>=85 状态充足`。
Core 同时返回主因、次因、校准天数、所需天数和置信度；平台不得从分数反推解释。

## 首页交互与表现

- 观测仪唤醒后仍是森林中的真实物件。点击物件会在首页左上方固定／取消一个小框，不打开 Sheet、弹窗、
  全屏报告或数据二楼；固定状态按当前 Pibo 身份跨启动保存；
- 卡片默认收拢，显示一个焦点分数、独立状态 chip、睡眠充足度、相对近期负荷和一句直接结论；
- 点击卡片标题区在原位展开，追加 Core 返回的两条主要依据、基线晚数和更新时间；展开状态只保留在当前会话；
- 卡片使用现有浅色 Moss Glass、睡眠靛蓝和小面积基础青绿，不使用垫图、角色插画、树纹、镜头、深色分享图
  或第二套设计系统；森林与 Pibo 始终是主视觉；
- 全屏页面、Half Sheet、发芽特写和好友来光提示出现时卡片暂时隐藏，回到裸首页后恢复；
- 没有权限、同步中断、当天睡眠缺失或个人基线不足时，卡片以直白原因和必要操作替代分数，不沿用上一天的
  数字冒充今天。
