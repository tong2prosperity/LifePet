# 决定 062：读数徽章

> 日期：2026-10-20
> 状态：已批准（2026-10-20，用户：「1，没问题。徽章。2，不退，现在还没人使用，没关系。3，状态栏写结论，数字放点击后的面板。」）
> 依据：用户 2026-10-20 提出——原来的状态观测仪还有没有必要；能否设计一段剧情，让 Pibo 直接佩戴这个装备，并在状态栏里直接映射用户的状态
> 范围：修订 047（状态观测仪统一悬浮查看）与 057（首页顶部 HUD）；第一季第 4 拍增加一段表现；iOS 不补齐（沿用 057）

## 1. 为什么

- 状态观测仪要花 3 枚 `bo` 才能看到自己的健康读数。这些数据是用户自己的，不应该被游戏货币挡住。
- 像素首页顶部已经有睡眠、步数、活动三枚能量小牌，Pibo 的六状态也在表达同一件事；场景里再立一个三脚架是第三处，入口也难找。
- Pibo 是来地球、给家里写报告的访客（059、第一季）。一个随身的采样器比摆在森林里的仪器更合它的身份。

## 2. 正史

Pibo 胸前别着一枚从舱里带出来的读数徽章，用来记录地球上的日子，好写报告寄回家。降落时摔裂了镜片：读数照常，镜片偶尔暗一下。第一季第 4 拍修好天线时，Pibo 顺手把徽章也拧紧了，镜片从此不再闪。

变形（061）时徽章留在形态上，和眼睛、`bo` 叶一样，是「变不掉」的部分。

## 3. 规则

1. **从第 1 天起每个人都有。** 不买、不解锁、不随剧情开放读数；剧情只改变徽章的样子（裂与不裂）。
2. **徽章的颜色就是 Core 六状态**：等待数据、睡着、初醒、安稳、活跃、疲倦，另外有庆祝；平台只把状态换成颜色，不新增阈值。
3. **状态栏写结论，不写数字。** 首页顶部原来的三枚能量小牌改为一条状态栏：徽章图标加一句今天的结论。结论来自 Core 的准备度分档；没有数据时写明原因，例如「个人基线正在建立」「还没有健康数据权限」，不编读数。今日能量来源仍在成长页。
4. **数字放在点开后的面板里。** 点状态栏打开读数面板，沿用 047 的内容与合同：今日准备度、睡眠充足度、近期负荷、主要依据、最近 7 日，以及权限、服务、数据不足时的回退。面板与状态栏共用同一句结论。
5. **单击 Pibo 不出文字**（沿用现有规则），只让徽章闪一下，发出读数声。
6. **状态观测仪退场。** 不在森林里出现，也不再作为可解锁物件。已有的拥有记录保留，不退回 `bo`（用户决定：目前还没有人用过）。物件、代码与 Core 目录不变，恢复只需改回发布范围常量。

## 4. 不做

- 不在状态栏显示分数、心率、HRV 等数字。
- 不因为读数推送通知，不催促（沿用 034、055）。
- 不新增 Core 规则、不改 Core 物件目录或成本。

## 5. 与旧决定的关系

- 047：读数的内容与回退合同保留；「不做角色佩戴」和「拥有观测仪才能查看」两条，由本决定替代。
- 057：首页顶部三枚能量小牌改为状态栏；成长页的今日来源保留。
