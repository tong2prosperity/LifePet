# 现有产品叙事承载盘点

> 日期：2026-07-29  
> 方法：读取当前 iOS 代码、运行 iPhone 17 Pro 模拟器、检查本仓库与 `pibo-assets` 资源。  
> 范围：只读盘点，不修改 App 代码、资产或产品行为。

## 结论

新故事不应建立一套与当前 App 平行的理想架构。当前产品已经具备完整的森林主页、角色舞台、健康功能入口、历史页、气泡、能量特写和拔取交互；后续叙事设计必须优先贴合这些已实现结构，只在无法承载关键故事时做小范围增补。

需要保护的是已经投入制作的视觉、动画、交互和功能资产，不是旧世界观赋予它们的含义。旧叙事逻辑若与新决定冲突，可以在保留资产的情况下重新解释或替换。

## 当前已经成立的产品骨架

### 1. 固定森林主页

- `HomeView` 使用全屏 `PiboStageView`；
- 生产环境只有 `forest` 一个主题；
- SpriteKit 负责森林、Pibo、头顶植物、天气、粒子和场景内交互；
- SwiftUI 负责问候、气泡、四个入口、弹层和全屏功能页；
- 森林已经具有时间光影、天气、风、雨、河流、前景植物互动和环境音。

这意味着“森林季”不需要重新创建。故事变化应优先采用现有森林上的状态变化、附加节点、光影、声音、Pibo 行为和少量新增物件，而不是新建一套主页框架。

### 2. 当前工程中的四个主页入口

当前右上角为 2×2 四个入口：

1. 露珠相机（新方案定名为“餐食相机”）；
2. 小游戏；
3. 足迹；
4. 设置。

这是代码盘点，不代表初版发布范围。初版相机只保留餐食拍摄、卡路里估算与记录；Walk Doodle 进入初版，但不再归类为小游戏；其余小游戏虽有工程代码，均不进入初版 App。后续入口布局应优先小改现有结构，故事回看若能进入“足迹”或复用现有弹层，就不新建顶层入口。

### 3. 现有全屏与弹层能力

主页已经稳定使用：

- `fullScreenCover`：相机、小游戏、足迹、Walk Doodle；其中除 Walk Doodle 外的小游戏不属于初版发布范围；
- `sheet`：设置、餐食详情、晨间睡眠卡；
- 主页遮罩与弹出卡：能量收集结果；
- SpriteKit 镜头拉近与一次性命令：发芽、拔取、转身、运动庆祝等。

漫画、短片、对话和关键选择应优先复用这些已有呈现方式，不先发明新的全局导航系统。

### 4. 已有故事接口

当前代码已经有：

- `PiboStorylineStore`：按顺序持久化已揭示线索；
- `StoryJournalView`：尚未接入入口的回看页雏形；
- Pibo 语音服务中的 `storyProgress`；
- 拍一拍触发故事线索的旧逻辑。

数据结构、持久化位置和回看页缝隙可以复用；其中“魔丸坠落”内容、随机拍一拍推进主线和旧章节规则不得直接沿用。

### 5. 已有能量和拔取资产

当前已经实现：

- 头顶植物的生长进度；
- 镜头拉近、抖动、生长、回到主页、弹出结果卡的能量流程；
- 拖动头顶植物和拔取动画；
- 拔取按钮、气泡、触感反馈和持久状态。

这些是事件 03 和长期 `bo` 循环最有价值的现成资产。后续应修改触发与叙事含义，而不是重新设计整套收集交互。

### 6. 已有“足迹”历史空间

当前足迹为全屏页面，内部已经包含：

- 足迹日记与趋势；
- 按日期查看睡眠、步数、身体信号、运动、餐食和涂鸦；
- 原版数据页；
- 自定义页面。

因此此前暂称的“共同记录”不是一个已确定的新页面。最小改动方向是研究如何在现有足迹中容纳已发生的故事事件，或把已有 `StoryJournalView` 接入足迹；是否这样做仍需正式讨论。

### 7. 已有森林与角色资产

- 本仓库 `Pibo/Resources/Forest/` 已有完整分层森林、河流、光线、石头、植物、Pibo 身体和椰壳睡眠窝；
- `pibo-assets` 已有 `sleep-1`、`sleep-2`、`awake` 等 nest 区域的角色状态；
- 椰壳睡眠窝已在当前森林运行时中出现；
- 用户提供的悬挂灯和风铃植物已有设计参考，但当前仓库尚未通过明确命名定位到对应运行时资源，后续需对照素材 ID，而不是重新设计。

## 新故事可以直接贴合的位置

| 新叙事需要 | 优先复用的现有能力 |
|---|---|
| 事件 01–02 初见与授权 | Onboarding 允许按新故事重构，可复用当前组件与 HealthKit 授权能力 |
| 事件 03 第一枚 `bo` | 正式森林主页、现有能量特写与拔取手势；触发改为真实数据自然积累 |
| 日常碎片和阶段停留台词 | 现有气泡、语音限额、空闲自言自语 |
| 主页故事提示 | Pibo 动作、气泡、现有场景节点和轻量遮罩 |
| 物件进入共同空间 | SpriteKit 森林分层节点和现有椰壳位置 |
| 重要短事件 | 现有镜头命令、SwiftUI overlay、sheet 或 full-screen cover |
| 故乡短片、漫画或选择 | 现有 full-screen cover / sheet 呈现结构 |
| 事件回看 | 现有足迹空间或未接入的 `StoryJournalView` |
| 环境逐渐变化 | 现有森林 renderer、时间光影、天气、音景与附加节点 |

## 必须替换含义、但可保留资产的旧实现

- 旧 onboarding 的“坠落、找光、命名、故障、契约失败”故事；
- 拍一拍以随机概率直接揭示下一条主线；
- 运动完成才驱动首次发芽的单一路径；
- 固定夜间窗口、等级好坏和错过即失去的拔取逻辑；
- 低步数或少睡让 Pibo 烦躁、受苦；
- 拍照默认产生认知能量；
- 魔丸阶段与旧人格弧。

这些实现可以提供组件、动画和代码缝隙，但其触发规则与叙事意义需要按新方案重写。涉及跨平台确定性规则时，正式实现必须先修改并发布 `pibo-core`，不能只在 Swift 中复制新阈值。

## 对后续工作的约束

1. 逐事件设计前，先指出复用哪个现有入口、组件、动画或资源；
2. 只有现有产品无法表达核心关系变化时，才提出新增页面或常驻入口；
3. 新增优先是状态、内容和局部组件，不是重新组织整个信息架构；
4. 所有“任务账本”“共同记录”“故事卡片”等词，在没有对应现有承载位置或明确小改方案前，只能视为占位概念；
5. 后续讨论功能与故事时，以当前运行代码为事实，不再用废弃的旧产品规格推导界面。
