# Pibo 六状态与动画表达

> 2026-09-05：用户确认先统一正式状态、名称和表达含义，再审阅动画，最后对应功能。
> 定义已确认；用户于 2026-09-06 授权将最新精修稿接入 iOS 与 HarmonyOS。
> v5.2 已接入两端原生播放器，含疲倦精修、持续休息、地面初醒、问候后、思考和双向食物观察。正式状态、原因和健康阈值仍以 Core 为准。

## 唯一正式状态清单

| Core / App ID | App 中文名称 | 状态含义 | 表情与身体表达 |
| --- | --- | --- | --- |
| `dataUnknown` | 等待数据 | 无法形成可靠状态判断 | 身体正常、神态中性，轻微观察头顶或身边；缺数据不表现为虚弱 |
| `sleeping` | 睡眠 | Core 作息睡眠阶段 | 闭眼躺卧、缓慢呼吸，普通互动不叫醒 |
| `waking` | 初醒 | 从睡眠向白天过渡 | 半睁眼、慢慢聚焦与起身；区分普通初醒和恢复不足 |
| `stable` | 安稳 | 正常平稳的日常状态 | 重心稳定、自然呼吸，偶尔认真观察 |
| `energetic` | 精神很好 | 现有真实睡眠/活动事件带来的状态 | 身体挺拔、目光有神、主动关注；日常待机不持续庆祝 |
| `tired` | 疲倦 | 睡眠不足或尚未达到 Core 恢复条件 | 眼皮沉重、身体下沉、回应迟缓，明显读出没有休息够 |

英文标识与 `PiboState` / `PiboActivityState` 一致，中文与 `PiboActivityState.displayName` 一致。动画标题使用「正式状态 · 行为」，不以“慢慢歇一会”“轻巧一跳”等动作描述替换状态名。

当前核对基线：两端精确锁定 Core 0.21.0（`913ecff92bfa10c8e7a87924d7365e84b0fe866e`）。阈值、原因、表达选择和转场意图由 Core 负责，平台只负责播放。

## 睡眠位置与吊床解锁

2026-09-05 用户再次明确：**吊床未解锁时，Pibo 睡在苔藓上；吊床解锁后，Pibo 睡在吊床里。**

| 吊床拥有情况 | 正式状态 | 睡眠表现 | 初醒位置 |
| --- | --- | --- | --- |
| 未解锁 | 睡眠 `sleeping` | 苔藓睡眠 | 从苔藓上起身 |
| 已解锁 | 睡眠 `sleeping` | 吊床睡眠 | 在吊床里醒来 |

解锁改变位置、承托和姿态，不改变健康状态，也不代表自动恢复。初醒时的普通/恢复不足表现仍消费现有 Core 结果。`HomeView` 把 `ornamentUnlocks.isUnlocked(.hammock)` 传给呈现控制器；`PiboAnimationStateMap.presentedAmbientStateID` 已按此切换地面/吊床资源，本轮不改这条运行逻辑或现有吊床 A/B 睡姿选择。

## 状态、行为与短暂表情

- **疲倦**：`insufficientSleep` 是现有原因。`tired.awake` 表现还醒着但身体很沉；进入 `tired.resting` 后持续侧倚/蜷缩休息。安顿好不代表恢复，动画结束不能回到清醒待机或擅自切换 `stable`。
- **初醒**：`waking.orienting` 为普通初醒情境；`waking.recovering` 根据待落定结果中的 `insufficientSleep` 表现恢复不足。问候后进入 `waking.greeted`，仍保留初醒及恢复不足的身体状况，不缩短 Core 初醒生命周期。
- **安稳**：保留 `stable.idle` 与 `stable.thinking` 的区别；思考不是新的健康状态。
- **精神很好**：`energetic.ready` 是常驻准备姿态；玩耍与活动庆祝是短暂动作/事件，不另建常驻健康状态。
- **等待数据**：权限、等待数据、来源不可用、无可信历史的中断属于说明情境。已有可信历史时继续沿用现有保留规则，不因动画需求制造疲倦。
- **好奇、疑惑、惊讶、愉快**：是状态上的短暂表情。地面与吊床是场景/姿态变体，也不增加主状态。

行为进入、持久化、事件消费和文本调度沿用决定 033 / 044。每次有效身体双击的即时动作与文本冷却仍分开；动画稿里的安顿过程不自行授权状态或行为推进。

## 本轮可审阅内容

设计目录：`pibo_design/animation-review-v5/`。

- 6 种基础状态待机；加安稳思考、疲倦持续休息、恢复不足初醒、两种初醒的问候后表现，共 11 种循环表现。
- 疲倦安顿、普通初醒起身、恢复不足初醒起身，3 段过程；过程结束后保持对应姿态。
- 11 种表现 × 左右食物的 22 个表达示例。视线先于身体，疲倦降低身体参与，休息保持侧倚，睡眠闭眼；餐食不改变主状态或 `bo`。
- 离线播放器、静音视频、状态与行为对照图、60 fps 设计采样、审阅意见导出。
- 苔藓/吊床睡眠同屏对照，使用已有森林苔藓纹理、吊床与批准的吊床睡姿；另有睡眠位置静音视频。

恢复不足初醒和吊床睡眠源形状来自 pibo-media 已批准资源。其他姿态按本次确认方向调整。两种睡眠位置均已接入；全新吊床起身编舞和吊床首次试用过程仍需另行制作。本批已完成原生播放与现有业务触发对应，真机持续帧率和耗电仍待实测。

## 2026-09-06 原生接入检查点

- 两端共用 `pibo-media` 角色资产 0.7.0 的 `PiboExpressions.json`：11 个循环、3 个转场、22 个食物观察，另保留已批准的 2.8 秒拍一拍，共 37 段。iOS 使用 SpriteKit，HarmonyOS 使用 Canvas；运行时无需设计目录或 WebView。
- 正式状态和表达选择使用 Core 0.21.0。疲倦安顿、初醒问候消费已有 episode 行为；过程结束保持休息／问候后的表现，直到现有业务规则改变状态。安稳思考的等待时长也由 Core 提供。
- 食物观察以当前身体姿态为基础叠加，视线朝向实际贴纸；结束恢复当前表现，睡眠保持闭眼。有效餐食、历史和奖励仍由已有成功条件决定。
- 疲倦眼睛使用连续圆润轮廓，缓慢开合；身体下沉时脚部保持落点。食物的横向伸缩改为相对原姿态，修复观察开始／结束时初醒和精神很好身体宽度突变。
- 减少动态效果使用对应静止姿态。连续拍一拍、食物中断、持续休息和 Shadow 原生渲染已验证。
- Core、iOS 全量测试与后续专项测试、鸿蒙全部检查、两端 Debug 构建及媒体同步检查通过。

[原生截图、静音录屏与复验方法](../animation-verification/2026-09-06/README.md)。两端 Debug「森林细节」面板可逐个选择表现，并用「观察左侧／观察右侧」按钮预演；预演不创建餐食记录。
