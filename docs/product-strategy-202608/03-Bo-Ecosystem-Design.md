# `bo` 生态与餐食相机结合方案

> **核心目标**：让“健康数据 → `bo` → 共同物件 → Pibo 新行为”成为可见的养成循环，同时把餐食相机从独立工具接回 Pibo 的共同生活。  
> **状态**：2026-08-23 已冻结成熟 `bo` 直接投入物件、单一角色渲染和睡眠能量落点方案；不再制作独立拔取、背包入账和库存悬浮窗。

## 一、`bo` 的完整交互闭环

```text
真实睡眠与活动
→ Core 计算 growthProgress
→ Pibo 身上发芽／成形／成熟
→ 用户点击成熟 bo 或灰态目标，检视下一个未唤醒物件
→ 用户确认把可用 bo 直接投入物件
→ 物件恢复生机
→ Pibo 立即体验并永久学会相关行为
```

任何一步如果只发生库存变化而没有 Pibo 的行为反馈，都不能视为完整养成闭环。

## 二、生长、成熟与直接投入

- 生长阶段由 Core 统一输出或定义，双端只负责呈现；
- Pibo 身上的阶段视觉优先于一条抽象进度条；
- 所有六种 Pibo 主状态共用一套 canonical `bo` 投影；状态只改变 Pibo 的身体与行为，不各自复制一套 `bo` 形象和获取动画；
- `bo` 成熟后仍附着在 Pibo 身上。点击成熟 `bo` 与点击灰态目标进入同一个物件检视 Half-sheet；
- 用户确认后由 Core 原子执行直接投入，优先消耗 `ripeCount`，再兼容消耗旧版本已经拔取的 `balance`；
- 首页不显示背包数量、独立“收下”按钮、拔取飞行或解锁物品进度窗；准确可用量、物件成本与不足数量集中显示在物件检视中；
- 多枚成熟 `bo` 继续由真实账本保存，但场景只显示一枚代表当前可投入状态的成熟 `bo`。投入后若仍有成熟库存，形象保持成熟；否则显示下一枚的真实生长进度；
- 关闭 Half-sheet 不扣除 `bo`，重复确认、余额不足和持久化失败都不得产生假唤醒。

旧 `pluck`／`balance` 数据只用于向后兼容和迁移，不再作为新用户必须理解的产品步骤。后续如增加美术反馈，只能强化“从 Pibo 到物件”的直接投入，不重建一次独立收取。

## 三、睡眠能量如何落到 Pibo

用户首次回到森林并有新的昨夜睡眠与 `bo` 能量变化时，使用同一场景完成四段因果：

1. 显示单一事实，例如“昨晚睡了 7 小时 12 分钟”；
2. 能量从事实提示移动到 Pibo 头顶的 canonical `bo`；
3. Pibo 做一次克制的接收反应；
4. `bo` 从提交前的真实进度生长到提交后的真实进度，并显示“bo 又长了一点”“bo 快形成了”或“一枚 bo 成熟了”。

已有成熟 `bo` 时不得为了演示而退回幼芽：能量仍落到同一位置，结果根据账本明确显示“下一枚 bo 又长了一点”或“又一枚 bo 成熟了”。Reduce Motion 下取消空间移动，但仍同时保留睡眠事实和生长结果。

这段基础因果反馈不依赖吊床所有权；吊床仍只门控详细睡眠回顾与相关自主行为。这样没有吊床的用户也能理解“昨晚的睡眠如何改变了 Pibo”，同时不会绕过物件能力。

## 四、物件唤醒与能力

首版只展示下一个可唤醒目标，不把四个物件全部以灰色模型堆在首页。

物件检视需要同时回答：

1. 这是什么；
2. 唤醒后 Pibo 会多会什么；
3. 需要多少 `bo`；
4. 当前可直接投入多少 `bo`；
5. 能量不足时还差多少。

唤醒后的能力仍由现有物件所有权和 Core capability 派生，不新增另一套技能背包。

当前第一目标保持为吊床。其永久结果不仅是开放睡眠回顾，而是让 Pibo 在 `sleeping` 与 `tired` 行为中真实使用吊床。

## 五、基础餐食相机定位

基础相机不是 `bo` 产出方式，也不是必须完成的一日三餐任务。它的首版定位是：

> **用户偶尔把正在吃的地球食物展示给 Pibo，Pibo 与用户共同观察并留下一条餐食记录。**

基础相机从首日开始可见，不再要求先累计 6 `bo` 或拥有补梦风铃。后续持续计算成本较高的高级分析、更多历史洞察或增强能力可以另行讨论收费，但不在本轮首版改造中决定。

## 六、相机入口（2026-08-17 实现确认）

首版相机继续使用首页右上角悬浮按钮，不把它改造成森林中的物理装置：

- 按钮从第一天已经可用，不需要注入 `bo`；
- 点击按钮进入当前已实现的餐次选择和真实相机流程；
- 从相机返回后仍然回到同一个森林，而不是结束在独立工具页面。

森林物理装置属于后续可选设计，不进入本轮无新增素材改造。

## 七、拍摄后的共同观察闭环

1. 用户选择餐次并拍摄真实照片；
2. 现有链路完成食物抠图、热量与营养估算；
3. 餐食详情保留可编辑的估算结果和识别状态；
4. 返回森林后，观察仪短暂投射食物抠图；
5. Pibo 靠近、低头或绕行观察；
6. Pibo 给出一句受控、简短、非评判性的观察；
7. 投影消退，记录继续保存在餐食历史中。

首版只需要一套可靠观察行为，不需要根据每一种食物制作独立动画。

## 八、餐食回应规则

后端模型不直接自由决定 Pibo 最终台词。后端负责返回结构化识别、营养估算、置信度和可用的观察事实；Pibo 的最终表达由受控内容键／模板和既有人格规则选择。

允许的方向：

- `颜色很亮。`
- `我记下了。`
- `这种形状，我第一次见。`
- 在识别可信时，简短描述主要食物构成。

不允许的方向：

- `你今天吃得很不健康。`
- `这么高碳水，看来你消耗很大。`
- 把单张照片推断成用户全天饮食；
- 用“好／坏”“自律／放纵”评价用户；
- 因未拍餐食让 Pibo 受苦、停止生长或发出负罪通知。

## 九、失败与降级

- **网络或识别失败**：显示轻量 Banner／Toast，保留照片和餐次选择，提供重试；如果已有可用抠图，可以让 Pibo 安静观察，但不能伪造热量结果；
- **抠图失败**：餐食记录仍可保留原图，森林投影使用原图的轻量卡片或跳过投影；
- **权限拒绝／设备不可用**：展示原因和设置入口，不生成模拟照片；
- **快速离开／重复拍摄**：沿用当前资源释放和过期回调隔离，不能生成重复记录；
- **所有失败**：不影响 Pibo 主状态、`bo`、吊床和其他养成进度。

## 十、补梦风铃的后续位置（待审批）

基础相机前置后，补梦风铃不再作为“能否使用相机”的硬门槛。可选方向是让它在后续增强共同观察，例如开放更丰富的投影、餐食记忆或其他持续服务；在具体价值被验证前，不应为了保留旧 entitlement 而人为限制基础相机。

Walk Doodle 与补梦风铃的关系保持待讨论，本文件不重新冻结。
