# Pibo 完整状态与上下文动作设计方案

> **目标**：把全局单一“拍一拍”升级为符合 Pibo 当前生命状态的直接互动，建立“看懂状态 → 给予照料 → Pibo 做出回应”的闭环。  
> **状态**：统一原则、六状态方向与入口方案已于 2026-08-17 经用户确认；具体资源 ID 和动画编排在实现阶段验收。

## 一、统一规则

1. **Core 主状态是健康事实**  
   iOS／HarmonyOS 只消费 Core 输出的 `dataUnknown`、`sleeping`、`waking`、`stable`、`energetic`、`tired` 及原因，不在 UI 层重算睡眠比例、步数或时间窗口。

2. **互动改变行为，不覆盖主状态**  
   用户可以让疲惫的 Pibo 被安顿好，但不能通过点击把 `tired` 变成 `stable`。建议将 `resting`、`comforted`、`playing` 等作为短暂表现／行为子状态。

3. **首版一个状态只有一个主要动作**  
   不做喂食、清洁、玩具等动作菜单。用户直接点击 Pibo 或状态对应物件，系统自动执行当前最符合直觉的动作。

4. **动作必须有可见结果**  
   不能只弹一句文案。Pibo 至少要改变姿态、位置、动画或对环境的使用方式。

5. **新健康事件优先**  
   Core 主状态切换时可以中断当前互动动画，进入新的真实状态。状态内动作不得阻塞健康事实更新。

6. **重复打扰是行为子状态**  
   连续快速点击可以触发现有 Pat V2 的被打扰／不耐烦表现，但不新增第七个健康主状态。

## 二、六状态方案（已确认）

### 1. `tired`：安顿休息

- **用户看到**：动作迟缓、眼睛半闭、身体重量下沉；有吊床时偶尔望向吊床。
- **主要动作**：`让它休息`。
- **无吊床**：Pibo 在当前位置或固定柔软区域蜷缩，呼吸逐渐平缓。
- **有吊床**：Pibo 主动走到吊床并躺下。
- **照料结果**：进入 `tired + resting/comforted` 表现，仍然保持疲惫语义；不在 30 分钟后伪装为 `stable`。
- **结束方式**：当前行为播放完成后保持状态适配的休息待机；后续真实健康事件切换主状态。
- **禁止**：出现“你没睡好，所以 Pibo 被你伤害”的归责文案。

### 2. `waking`：早安确认

- **用户看到**：迷糊、揉眼、轻微打哈欠或恢复不足的迟缓表现。
- **主要动作**：`和它说早安`。
- **表现**：Pibo 看向用户并伸展身体；恢复良好与恢复不足可以使用不同幅度，但不需要长篇文字。
- **照料结果**：完成一次双方开始新一天的确认，不跳过 Core 的初醒生命周期。
- **有吊床**：动作从吊床起身开始；无吊床使用地面初醒资源。

### 3. `energetic`：释放精力

- **用户看到**：更高的重心、轻快呼吸、主动观察环境、短促跃动或发光细节，必须与 `stable` 在静态截图和动画中都可区分。
- **主要动作**：`让它去玩`／`跟它玩一下`。
- **表现**：Pibo 执行一段短探索，例如冲向场景边缘、跳跃、围绕物件观察或完成一个小回环。
- **照料结果**：进入 `energetic + playing/exploring`，结束后仍保持精力充足待机。
- **禁止**：把运动里程碑的短庆祝动画直接当作整个 `energetic` 常驻资源。

### 4. `stable`：日常确认

- **用户看到**：稳定呼吸、自主张望、偶尔观察附近物件。
- **主要动作**：`摸一摸`／普通 Check-in。
- **表现**：Pibo 转向用户、偏头或靠近，配合轻触觉反馈。
- **照料结果**：短暂回应后回到稳定生活，不强行制造奖励。
- **重复点击**：进入被打扰表现，沿用 Pat V2 的次数、冷却和台词预算。

### 5. `sleeping`：不叫醒的照料

- **用户看到**：有吊床时在吊床睡眠，无吊床时地面睡眠；保持已有动态睡眠周期。
- **主要动作**：`轻轻看一眼`／`让它继续睡`。
- **表现**：场景边缘轻微变暗、呼吸短暂变得更平稳，或播放非常小的睡眠回应；不能因为普通点击直接叫醒。
- **照料结果**：保持 `sleeping`，用户得到“我没有打扰它”的明确反馈。
- **重复打扰**：可以出现一次翻身或不耐烦，但是否允许真正进入“被打扰”表现需在动画评审时确认。

### 6. `dataUnknown`：检查连接

- **用户看到**：Pibo 保持安全、非受苦姿态，头花或观察动作表现为“暂时没有接收到生命信号”，不得复用 `tired`。
- **主要动作**：`看看发生了什么`。
- **表现**：Pibo 检查自己的头花或观测装置，同时打开轻量状态说明。
- **说明内容**：区分尚未授权、暂无足够数据、同步暂时中断、数据来源不可用。
- **照料结果**：能修复时提供授权／设置入口；不能修复时告诉用户稍后会自动重试。
- **禁止**：因缺数据扣 `bo`、触发冰封、推断低健康或责备用户。

## 三、入口与 UI 方案（已确认）

- 首页不常驻六个文字按钮；点击 Pibo 是统一入口；
- 首次进入某个状态时，可在 Pibo 附近短暂显示动作提示，例如“让它休息”；
- 如果保留 Chrome 动作图标，图标只提示当前动作，不承担第二套状态判断；
- 状态对应物件存在时允许直接点击物件，例如疲惫时点击吊床；
- 动作执行中再次点击不重复启动同一动画；
- VoiceOver 需要读出“Pibo 当前疲惫，可让它休息”等明确语义。

## 四、首版动画最小清单（待资源确认）

| Core 主状态 | 必须有的常驻表现 | 必须有的互动行为 |
|---|---|---|
| `dataUnknown` | 安全的信号未知待机 | 检查头花／装置 |
| `sleeping` | 地面睡眠＋吊床睡眠 | 不叫醒的轻回应 |
| `waking` | 普通初醒＋恢复不足初醒 | 看向用户并伸展 |
| `stable` | 稳定待机 | 日常回应 |
| `energetic` | 独立精力充足待机 | 短探索／玩耍 |
| `tired` | 疲惫待机 | 地面休息＋吊床休息 |

审批后再把上述语义映射成稳定的 Core 动画意图和 `pibo-media` 资源 ID，平台不自行发明跨端阈值或内容选择规则。
