# Pibo 小游戏设计 / UI / 性能审计

> 2026-07-10 基线。覆盖 `MiniGameKind.allCases` 的 23 个入口。当前结论来自源码审查、iPhone 17 Pro（iOS 26.5）Simulator 逐款交互与一条符号化 ETTrace；相机、麦克风、计步、Core Motion、音频时序、GPS、拖拽手感和最终能耗仍须真机复核。

## 验收标准

- 玩法：用户在首屏能理解目标、输入与失败条件；视觉反馈必须和判定一致；短局原则上不超过 90 秒。
- UI/UX：关键输入有即时反馈；暂停和切后台不偷跑；权限型游戏先解释再请求，并始终提供可理解的降级路径。
- 性能：不以高频 `Timer.publish` 修改顶层 `@State` 来驱动整页；时间和物理基于真实时间差；高频渲染限制在舞台子树；离场后传感器、相机、麦克风与任务全部停止。
- 产品：认知类只描述被训练任务本身；结算保留 3 星、最佳成绩和花瓣奖励，并继续补齐研究文档要求的主循环回流。

## 跨游戏问题

1. 实时游戏已改用独立单调 / 真实时间模型或舞台局部 `TimelineView`；倒计时、物理步进、呼吸相位和限时答题窗口统一使用单调 uptime，只有放置花田持久化和相机帧新鲜度保留墙上时钟语义。`Timer.publish` 已从小游戏实现中移除，高频状态收窄到舞台子树，暂停 / 结果页会取消模拟与监测任务。Flower Merge 的符号化 Simulator ETTrace 未发现 first-party 主线程热点；真机仍需用 Instruments 复核帧率和能耗。
2. 已修复的实时游戏均已接入后台暂停语义；倒计时使用单调时钟，展示 / 反馈延迟使用可取消任务，不再以累计 tick 推进局时。Simulator 已覆盖代表性的开始、暂停、继续、重来和离场取消；传感器 / 相机 / 麦克风相关暂停仍需真机复核。
3. `MirrorPetals` 与 `MistBreath` 已改为权限前说明和手动降级路径，但相机架机、麦克风灵敏度、拒绝权限后的恢复仍需要真机矩阵验收。
4. 3 星、最佳成绩和花瓣余额已接入，但“能量 / 头顶花状态 / 碎片或装扮”的多线结算尚未实现。该缺口是产品主循环问题，不应靠继续增加孤立货币掩盖。
5. 拖动、点按、按住和空间移动舞台均已补充 VoiceOver 可调操作或命名动作，结算层会取得无障碍焦点并隐藏底层游戏子树；横屏已由共享壳切成“HUD / 可滚动控制区 + 舞台”双栏，显式动画遵循 Reduce Motion。AXXXL 已覆盖目录、Memory Matrix、华容道、猜拳、地图涂鸦、共享结算卡和横屏共享壳；原生 AX 树已验证华容道四向动作、迷雾“吹一口”、列车颜色状态和 Pibo 漂浮距离状态。小屏、系统 VoiceOver 实际导航与 Reduce Motion 视觉节奏仍需真机复核。
6. 所有会计时、生成障碍或自动推进题目的游戏都已增加显式“开始”状态，首屏阅读说明时不再偷走局时。
