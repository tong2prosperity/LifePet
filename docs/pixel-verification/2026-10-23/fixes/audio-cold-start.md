# 冷启动静音与音频会话恢复

用户反馈：Xcode 直接运行没有声音，退出再打开后恢复。

检查发现环境音在后台 `setActive` 完成前便把 `sessionActive` 和
`holdsPlaybackSession` 设为 true，主线程随即预备／播放播放器；激活失败、播放返回
false 时没有可靠的就地恢复。短音效预加载和收取音还会在独立队列切换进程唯一的
AVAudioSession，激活／停用可能交错。这些问题能解释启动时静音、重走生命周期后恢复，
但没有把模拟器验证等同于用户真机上的直接复现。

修复：

- `PiboAudioRuntime` 统一后台队列和会话状态。只有激活成功才记录当前类别；环境音
  实际持有播放会话时，短音效不会把它切回 ambient。
- 环境音、短音效和收取音的解码、预备、播放、停止均在这条队列执行；播放返回 false
  会丢弃失效播放器和会话缓存。
- 音效预加载等待场景 active；环境音回前台会重新读取声音抑制提示并恢复当前混音。
- 中断和系统音频服务重置会清理失效状态；暂时启动失败按 0.25／0.75／1.5 秒间隔有限
  重试，停止或混音变更会取消旧重试／延迟停用。
- 增加会话激活成功、实际播放器启动和失败日志，便于区分“请求播放”与“播放已接受”。

验证：iPhone 17／iOS 26.5 Simulator 全量 472 项、92 个 suite 通过；新增 7 项启动回归，
覆盖激活延迟、类别竞争、首次失败、无需离开首页的自动恢复、停止取消、失效播放器和
系统重置。Debug 与 Release 模拟器构建通过。

实际模拟器日志也确认了冷启动和同一进程从后台返回两条路径：均先记录会话激活成功，
再记录三条环境音播放器启动成功；未出现音频主线程阻塞警告。

设备输出是否可闻仍需真机复测；单元测试的播放器／会话替身不作为可闻性证据。
