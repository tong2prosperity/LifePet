# iOS 上拉收取修复（2026-10-25）

本轮只排查和修改 iOS 收取路径，Core 固定版本及健康能量规则保持不变。

> 后续澄清：用户指的是「整个 Pibo 形象消失」。本页记录的防重复提交及反馈修复未覆盖返家陪伴状态；实际角色隐藏根因与修复见[补充复现记录](../actor-disappearance/README.md)。

## 发现与修复

1. `PixelStageRenderer.collect()` 在同步回调结束后立即撤下保护，但 SwiftUI 在同一手势中仍会持续发送 `onChanged`。存在暂存能量或旧成熟队列时，一次上拉可能收取多枚。新增本次拖动的提交标记，成功和失败都只提交一次，松手或离开前台后才允许下一次手势。
2. 拖动每次都用变化后的叶子命中框重新检测原始起点，可能中途失去手势。现在首次拖动时确定归属，保持到松手；退到后台和退出页面时清理。
3. 收取后只有短暂散开光点，随后叶子缩为下一轮充能的小芽，缺少清楚的去向说明；Pibo 同时可能继续走动。收取成功明确显示「已存入库存 · +1 bo」，回弹和提示期间暂停普通移动，常驻 HUD 保留实际余额。失败保留成熟状态、回弹并提示重试。

账本原有同步落盘机制正常，本轮未发现成功收取后余额被清空的证据。头顶的成熟能量在收取后进入余额，空的小芽继续充能；未删除或补发用户资产。

- 窗口测试验证收取提示结束后余额仍为 1，角色持续可见。
