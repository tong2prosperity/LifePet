# 2026-10-29 体验修复复审

复审 2026-10-28 的七项体验改动，发现并修复以下问题；不覆盖工作区原有健康记录和 Widget 修复。

| 优先级 | 问题与触发场景 | 修复 |
| --- | --- | --- |
| P1 | 心愿先标记 rewarded，再写经验；两次写入之间退出会丢奖励，反向重试又缺少幂等凭据。反馈队列曾在 XP 尚为空时先持久化。 | 成长快照一次提交经验、计数、带真实 XP 的反馈及当日结算凭据。心愿仅在拿到凭据后标记已结算，重启可重放同一凭据；缺少当天健康值也可继续结算已完成心愿。未结算时如实显示「奖励结算中」。 |
| P1 | 关闭编辑器隐式保存；清空名字会阻止退出。改名字和改份量分两次保存，存在部分成功。 | 「完成／保存调整」显式保存，关闭丢弃草稿。名称、餐次及份量在同一次 SwiftData 保存中提交，失败恢复原记录。只打开份量编辑不改动原估算。 |
| P1 | 草稿直接与实时记录比较，后台重试改名后，未编辑的旧名称会被误判为用户修改并覆盖新结果；按餐次打开的页还可能在改餐次后丢失原记录。 | 草稿比较加载时的基线并锁定照片 UUID；未改草稿可随重试刷新，已改草稿保留。识别重试保留用户已确认名字和餐次；记录已删除或保存失败返回失败。 |
| P2 | 结果页只在观察结束时尝试打开一次，遇到其他弹层就丢失；拍照前后还有独立的八秒过期标签。 | 结果 UUID 移到 HomePresentationState 的待展示队列；等待相机、观察、其他弹层及关闭动画结束后重试，成功展示后才消费。会话结束清队列；保留相机关闭后才呈现观察的顺序。 |
| P2 | 趣味台词绕过原有拍拍冷却，下一次普通拍拍还可能立即说话；若替换普通台词则可能吃掉未展示的微章节。 | 专用台词使用同一个 PatConversationStore 时钟并调用现有 Core 冷却 API，不推进章节游标。动作与计数不受文字冷却影响。 |
| P2 | 第一轮健康刷新前的拍拍会用 cameraEnabled/companionEnabled=true 和空基线生成全天计划，提前冻结错误的任务集合。 | 没有配置上下文时先存互动，不猜测每日计划；已有当天心愿仍能更新，后续刷新使用真实功能开关及基线规划并带入先前计数。跨日只复用基线和功能开关，不复用昨日健康事实。 |

登录邀请现在还检查前台状态、弹层关闭动画和待展示餐食结果；执行其他心愿不会悄悄把邀请永久标记为已跳过。拍拍任务完成时，即使当前问答占用了说话机会，也会结束任务提示。
