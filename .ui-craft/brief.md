# Product purpose

Pibo 把用户通过 HealthKit 已经产生的真实睡眠与活动数据，转化为一只会改变状态、长出 `bo` 并逐渐学会新生活行为的虚拟宠物。

# Primary user

已经用 iPhone／Apple Watch／HealthKit 被动记录睡眠和活动，不喜欢数字报表和高频打卡，但愿意每天用一两个短会话查看并照料 Pibo 的 iPhone 用户。

# Principles

1. **真实健康事实高于点击反馈。** 点击可以安顿、问候或陪玩，不能伪造恢复、精力或 `bo`。
2. **变化先落在 Pibo 身上。** 状态、成长和解锁必须通过 Pibo 的身体、动作或自主生活可见，功能入口和库存只是辅助。
3. **一个时刻只给一个直觉动作。** 首页不增加宠物数值、动作菜单或功能卡墙；直接点击 Pibo 执行当前状态最合理的动作。
4. **永久成长是学会生活。** 首版不做等级与进化树；共同物件必须让 Pibo 永久增加可观察行为。
5. **首日价值不靠伪造。** 不赠送假的健康 `bo`，不强制三餐或连续签到；用真实状态、一次照料和可选相机建立价值。

# Success metric for Home

用户在不阅读说明的情况下能分辨 Pibo 当前的大类状态，知道点击后能做什么，并能理解第一枚真实 `bo` 最终让 Pibo 永久学会使用吊床。

# Out of scope

- 不新增饥饿、清洁、等级、经验、死亡或外形进化系统。
- 不重建 Studio、Gym、TabView、数据二楼或横向场景漫游。
- 不在本轮实现 Stasis、Shadow Pibo、好友、商店、战斗或其他小游戏。
- 不让餐食、网络错误、权限拒绝或缺失数据伤害 Pibo 或影响 `bo`。
- 不在平台层复制 `pibo-core` 的健康阈值、确定性动作和动画选择规则。

# Learned constraints

- **2026-08-17** — Pibo 正式采用“由真实健康数据养成的虚拟宠物”定义。*Why:* 旧的镜子／共同经历者解释不足以形成直接可理解的首版养成循环。
- **2026-08-17** — Shadow Pibo 的隐私风险不作为产品阻塞项。*Why:* 当前优先验证状态映射与养成，不扩展隐私设计讨论。
- **2026-08-17** — 基础餐食相机首日可见且可选，不由补梦风铃门控。*Why:* 现有相机能力需要尽早被发现，但不能变成三餐打卡负担。
- **2026-08-17** — 相机继续使用首页右上角悬浮按钮，不制作森林物理装置。*Why:* 本轮不增加素材与额外场景工作量。
- **2026-08-17** — 首页一次只展示一个灰态的下一个共同物件，点击物件打开 Half-sheet，不保留目录／进度窗口。*Why:* 让成长目标留在共同空间内，并避免商店式入口。
- **2026-08-17** — HealthKit 持续异常必须使用可点的角色状态或首页提示，不能只用短时 Toast。*Why:* 用户需要知道当前判断依据并能恢复连接。
- **2026-08-17** — 瞬时错误用 Toast／Banner，持续健康数据异常必须有 `dataUnknown` 状态。*Why:* 一次性提示无法解释持续存在的角色状态。
- **2026-08-17** — 首页保持固定竖屏森林和现有插画语言。*Why:* Pibo 与环境是产品主体，不能退化成卡片仪表盘或通用 AI 风 UI。
