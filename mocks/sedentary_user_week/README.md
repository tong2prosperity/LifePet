- `generate.py` —— 生成器（种子 `20260602`）。

## 与 active 组的关键差异（这才是对照组的价值）

| 维度 | active（阿凯） | sedentary（小默） | 用途 |
|---|---|---|---|
| 步数 | 8k–25k | 1.1k–5.4k | 体力基本盘几乎吃不饱 |
| 运动分钟 | 38–168 | 0–12 | 多天为 0 → 触发「慢性死·10 天零运动」累计 |
| Workout | 天天有，类型丰富 | 仅周六一次散步 | 建议卡几乎无法自动翻牌 |
| 静息心率 / HRV | 49 / 60–78 | 73 / 27–36 | 心情维度持续低 → 逼近「急性死·心情<30 连续 7 天」 |
| 睡眠 | 每晚 6.5–8.4h | 碎觉 5–7h，**2 晚无数据** | 精力维度低 + 测「睡眠数据缺失」兜底 |
| 站立小时 | 10–13 达标 | 3–7 达标，其余 `idle` | 驱动久坐提醒玩法 |
| 机型 | Series 9（全传感器） | **SE（无血氧/手腕温度）** | 测 C 档数据缺失时不崩 |
| 健康事件 | 无 | highHeartRate / lowCardioFitness | C 档亚健康信号 |

## 刻意埋的边界 case（测兜底逻辑用）

1. **整晚缺睡眠数据**（周二、周五没戴表）——`sleepAnalysis` 当天完全没有记录。验证「精力维度在数据缺失时如何处理」：是按 0 算（会饿死）还是沿用上次值/不衰减？
2. **C 档数据天然缺失**——SE 机型全程没有 `oxygenSaturation` / `appleSleepingWristTemperature`。验证依赖这些字段的代码不会空指针。
3. **`appleStandHour=idle`**——除达标小时外，工作时段整点都标了 `idle`，可直接喂久坐提醒。
4. **连续多天运动分钟=0 / 步数极低**——把这 7 天接到第 8 天之后，应能触发慢性死/饿死累计计数。
5. **健康事件**——`highHeartRateEvent`、`lowCardioFitnessEvent` 作为 category 事件出现，可做「TA 最近压力有点大」类轻量提示。

## 用法

```bash
cd mocks/sedentary_user_week && python3 generate.py

# 对比两组某指标，例如运动分钟
for f in active_user_week sedentary_user_week; do
  echo "== $f =="; grep '"appleExerciseTime"' ../$f/$f.jsonl
done
```

> 想造更极端的「濒死」数据（连续 10+ 天零运动）：复制本目录，把 PLAN 扩到 14 天、workout 全 None、steps 压到 <1000 即可。
